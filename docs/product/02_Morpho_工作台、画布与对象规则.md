# Morpho v3：工作台、画布与对象规则

> **文档角色**：规定用户在 Morpho 中看见什么、如何在连续画布上放置和操作对象，以及对象、关系、交付引用与 Undo / Redo 的边界。  
> **配套阅读**：AI 行为和阶段 Context 见《03_Morpho_AI工作流程、阶段Context与连续性机制.md》；状态、版本、锚点和项目记录见《04_Morpho_状态、版本、项目记录与记忆.md》；项目首页、资产、搜索、导入与归档见《05_Morpho_项目入口、资产、搜索、导入与归档.md》。  
> **继承说明**：本文件以交接稿中已确认的画布操作为主，合并 v1 / v2 的工作台和对象基础规则；明确替换右侧 Inspector、阶段位置决定语义、Compare 固定专区、常驻生成队列等旧表述。完整来源见《00_Morpho_v3_规则继承、覆盖与完整性账本.md》。

## 1. 工作台总结构

Morpho 的用户可见工作方式始终是：

```text
一个连续项目窗口
+ 一张连续画布
+ 一个连续右侧聊天
```

工作台由五部分构成：

| 区域 | 主要作用 | 不承担什么 |
|---|---|---|
| 顶部 | 项目名称、基础操作、进入项目级入口 | 不做项目进度看板 |
| 左侧 | 轻量导航、资产、隐藏内容、项目级入口 | 不切换右侧 AI 成另一个聊天 |
| 中央画布 | 放置、阅读、比较、组织项目对象与交付内容 | 不强制节点工作流或固定表格流程 |
| 右侧 | 持续 AI 聊天与确认卡 | 不变成对象属性面板 |
| 底部详情栏 | 按需查看对象信息、来源、版本、关联、决策 | 不常驻展示所有元数据 |

### 1.1 顶部

顶部保持轻量，至少承担：

```text
项目名称
返回项目首页
导入入口
搜索入口
输出 / 归档入口
基础视图控制
```

不把阶段完成度、任务数量、多人动态、模型参数和操作历史铺成一排常驻状态。

### 1.2 左侧

左侧默认可收起。展开后提供：

```text
阶段 / 区域导航
资产
已隐藏内容
项目级输出与归档入口
```

阶段导航的作用是定位画布区域，帮助用户找回内容；**点击它不会改变当前 AI 工作重点、不会开一个新聊天，也不会让右侧变成对应阶段的专属面板。**

### 1.3 右侧

右侧始终是连续聊天。用户选中对象时，选中内容以轻量 Context 标签加入聊天输入；对象详细属性不占用右侧空间。

确认卡同样出现在聊天中，不弹出遮罩式窗口，不中断用户继续提问。

#### 选择对象后的可编辑建议

选中单个或多个对象后，系统可根据**对象类型、数量与直接关系**提供 2–4 个短建议，帮助用户知道如何把当前对象带入对话。建议出现于输入框附近或选择 Context 标签下方，不做遮罩式弹窗，也不抢占画布。

点击建议只会把一句可编辑的自然语言填入输入框；用户可以改写、补充、删除或直接发送。它**不会自动发送、不会自动执行、不会自动切换当前工作重点**。

| 选择对象 | 可出现的建议示例 |
|---|---|
| 文档 / 文件 | 读取并整理要求、提取项目限制、找待确认问题 |
| 单张参考图 | 分析形态与风格、提取可借用局部、作为参考继续生成 |
| 单张方案图 | 继续发展、局部修改、生成其他角度、生成使用场景 |
| 多张图 / 混合对象 | 比较这些对象、找共同线索、分析差异与风险、作为多参考生成 |
| 关键结论 / 设计定义 / 方向 | 整理为设计定义、提出方向变体、生成预览、检查与当前方向的关系 |
| 交付模块 | 检查交付缺口、整理本页内容、补充图注与说明 |

建议是可发现性辅助，不是固定操作菜单；用户仍可直接用自然语言提出任何任务。

### 1.4 底部详情栏

底部详情栏随对象选择出现，默认使用：

```text
[信息] [来源] [版本] [关联] [决策]
```

具体对象不一定每个页签都有内容；没有内容时不硬显示。详情栏用于按需追溯，不取代画布阅读，也不要求用户日常查看内部项目记录。

## 2. 画布空间：帮助阅读，不定义对象含义

### 2.1 默认阅读方式

画布通常从左到右呈现项目推进：

```text
输入 / 调研
→ 设计定义
→ 方向与视觉发展
→ 交付准备
```

上下空间可用于：

```text
方向分叉
视觉路线
局部探索
对照材料
交付分区
```

这是阅读和默认落点规则，不是对象语义规则。

### 2.2 位置不改变对象语义

以下内容不能由对象放在什么位置决定：

```text
对象类型
来源关系
版本关系
方向状态
是否纳入设计定义
是否是锚点
是否用于交付
是否已淘汰
```

普通拖动只改变位置。用户把一张主图拖回调研区附近，不会让它自动变成调研资料；把一张参考图放在主图旁边，也不会让它自动加入当前方向。

### 2.3 阶段区域

阶段区域是轻量视觉组织：帮助用户看清项目处于哪些重点、AI 结果默认应放到哪里、交付内容通常聚集在哪里。

区域不应：

- 像任务看板一样强制卡片流转；
- 因对象进入 / 离开区域而自动改变状态；
- 使对象无法跨区域比较、拖动或引用；
- 把 Compare 固定成一个必须经过的专区。

Compare 是局部操作，可在方向、主图或交付内容附近发起。

## 3. 画布对象

### 3.1 对象类型总表

| 对象 | 典型来源 | 主要用途 | 画布上的基本表现 |
|---|---|---|---|
| 图片 | 粘贴、拖入、AI 生成、文档提取 | 参考、预览、主图、场景、CMF、示意、交付引用源 | 缩略图与必要角色信息 |
| 文件 | PDF、PPT、Word、其他资料 | 作为原始资料阅读、提取、引用 | 文件名、类型、预览入口 |
| 链接 | 拖入 / 粘贴 URL | 保留网页或在线来源入口 | 域名、标题或链接摘要 |
| 文本 | 粘贴文字、用户记录、AI 草稿 | 说明、原始想法、简短笔记 | 可编辑文本块 |
| 研究与分析 | AI 基于指定资料生成 | 形成候选洞察、约束和机会 | 结构化分析卡 / 可展开内容 |
| 关键结论 | 用户明确保留的发现 | 进入定义、方向或后续判断 | 短结论对象与来源指向 |
| 设计定义 | 用户应用后的当前有效设计依据 | 规定问题、目标、原则、边界 | 重点定义对象 |
| 概念方向 | 一条独立策略、产品逻辑或总体架构 | 用于预览、比较、主 / 备选 / 淘汰判断 | 方向卡与相关预览 |
| 图像合集 | 一批导入图或一批生成结果 | 视觉整理与批次阅读 | 可展开集合，不是文件夹 |
| 组合 | 用户将多个对象临时布置在一起 | 布局整理 | 可一起移动的容器 |
| 交付模块 | 展板、PPT、作品集等的可编辑结构 | 汇集稳定引用、文字和布局 | 交付区域中的模块 |
| 说明标注 | 用户希望长期保留的圈选、箭头、编号和文字 | 解释、比较或交付表达 | 覆盖于对象附近的独立说明层 |

状态、版本、锚点和修订不在此文件重复规定，见《04_Morpho_状态、版本、项目记录与记忆.md》。

### 3.2 原始资料对象

原始资料保持原样：原文件名、文件类型、缩略图或预览、链接来源。系统不会因为用户一时说“这些都是竞品”就永久把每个对象改名、贴标签或搬进某个“竞品文件夹”。

用户可以在聊天里自然说明：

> 左边这几张是竞品，右边那两张是我之前的草图。

该说明可作为当前任务的语境；是否成为跨阶段稳定信息，由用户后续明确确认，而不是系统擅自写入项目记忆。

### 3.3 研究与分析、关键结论与设计定义

- **研究与分析**是 AI 对指定资料形成的候选理解，可继续讨论、补证或推翻；
- **关键结论**是用户明确保留、会影响后续判断的发现；
- **设计定义**是用户应用后的当前有效项目依据。

它们不是普通文本，也不能因拖动到某个区域就改变身份。需要转成展板 / PPT 文案时，使用“用于交付”生成可编辑摘要或引用，不直接把内部对象变成字面交付块。

### 3.4 概念方向与方案图

概念方向是策略或核心逻辑的对象；预览图、主图、场景图和示意图是围绕方向发展出来的视觉对象。

方向状态、视觉路线和版本关系不靠“放在同一列”判断，而由明确对象关系与用户决定维护。方向附近的空间只是让人更容易阅读其预览和分支。

## 4. 选择、空白点击与多选

### 4.1 单选

点击对象后：

```text
对象获得选择态
→ 底部详情栏切换到该对象
→ 对象成为右侧聊天的轻量 Context 标签
```

选择对象不自动切换当前 AI 工作重点。用户在方向与视觉发展时点击早期研究图，它只是当前输入，不会让系统自动回到调研。

### 4.2 多选

用户可框选或按常规多选方式选择多个对象。多选用于：

```text
一起移动
一起隐藏 / 锁定 / 删除
组合
拖入交付区创建多个引用
作为 AI 的共同输入
发起 Compare
```

跨阶段多选时，系统不强制将它们重新分组或要求用户先声明类别。只有当用户的意图确实不清楚且不同理解会导致不同结果时，AI 才做一个必要追问。

### 4.3 选择建议的范围与边界

选择建议只依据当前可见的选择结果和已知的直接对象关系生成，不让 AI 在后台持续观察用户是否满意或是否“做完一个阶段”。建议不因为用户刚看完一张卡片或刚收到一组生成图就立刻弹出。

当研究与分析、设计定义、方向等关键成果已经出现时，系统可以准备下一步建议；在用户下一次聚焦聊天输入框、主动打开建议或准备继续操作时再轻量呈现，例如：

```text
[继续补资料] [保留关键结论]
[整理为设计定义] [继续修改定义]
[生成预览] [再探索一个方向]
```

这些建议只说明“当前已有内容可以怎样继续”，不表示阶段完成。用户可以继续当前工作、采用下一步、忽略或关闭建议。

### 4.4 点击空白画布

点击空白画布只清除：

```text
选择状态
对象 Context 标签
临时高亮
临时关系线
```

不会清除：

```text
聊天记录
当前工作重点
输入框中未发送文字
正在执行的任务
AI 已经形成的项目理解
```

## 5. 合集与组合

### 5.1 合集：一批视觉内容的画布整理

合集用于一批导入图片或一批生成结果的初步阅读和收纳。

创建规则：

```text
批量导入视觉资料
→ 创建合集

一次 AI 返回一组视觉结果
→ 创建合集
```

合集初次出现时默认展开并聚焦，便于用户先看差异；之后由用户自行折叠、展开或移出成员。

合集不是：

```text
语义分类
永久文件夹
方向状态容器
版本链容器
用户必须维护的资产目录
```

合集中的每一张图仍独立：可选择、拖出、Compare、作为 AI 输入、继续发展、用于交付或删除。

### 5.2 组合：只解决布局

组合是用户把多个对象临时组织为一个布局单元。它可以整体移动、缩放或解散，但不改变：

```text
对象类型
来源 / 版本 / 关联
状态
是否被纳入设计定义
是否用于交付
```

组合不能嵌套合集，也不应发展成复杂的文件夹系统。

## 6. 隐藏、锁定、复制、移动与删除

### 6.1 隐藏

隐藏只让对象暂时从画布中消失，便于用户专注当前内容。

隐藏不会：

```text
删除对象
将对象设为已淘汰
改变对象状态
写入决定记录
让 AI 继续把它当作默认输入
```

AI 不读取隐藏内容，除非用户恢复、选中或明确提到它。恢复入口与搜索行为见《05_Morpho_项目入口、资产、搜索、导入与归档.md》。

### 6.2 锁定

锁定只锁布局，防止误移动、缩放、裁切或误删。

锁定对象仍可：

```text
查看
讨论
作为 AI 输入
读取来源、版本和关联
被用于交付
```

### 6.3 复制

普通复制适用于图片、文件、文本、标注、合集、组合和交付内容。复制后得到独立画布实例，原对象不变。

关键结论、设计定义和概念方向不使用“复制”来制造第二个并列事实：

```text
关键结论 → 新增结论或修订原结论
设计定义 → 创建修订草稿并应用
概念方向 → 创建方向变体
```

### 6.4 移动

移动只调整画布位置，不改变对象的来源、版本、状态、阶段语义或项目关系。

### 6.5 删除与已淘汰

删除就是删除。它适用于无用的普通对象、误导入资料、错误文字、不要的图像结果或用户明确不想保留的内容。

已淘汰只适用于仍值得保留历史、原因或可借用局部的概念方向。隐藏、删除和淘汰不能混为一种“归档”动作。

## 7. 交付区域与稳定引用

### 7.1 交付区始终可用

用户不必等到项目“完成”才把内容放进交付区。展板、PPT、作品集或其他交付模块可以在项目中途出现，用来检验表达是否缺内容。

### 7.2 拖入交付区创建引用实例

图片、文件、文本、标注、合集成员等拖入交付区时，创建的是**独立的稳定引用实例**：

```text
源对象仍留在原画布位置
交付区得到可裁切、可布局、可替换的引用实例
源对象后续移动、删除或出现新版本，不静默改变交付内容
```

这样用户可以把当前图放到展板里试排，而不担心上游迭代会把已经排好的模块自动替换掉。

### 7.3 不直接作为字面交付块的对象

研究与分析、关键结论、设计定义、概念方向不能直接拖成最终交付文本块。用户可以通过“用于交付”把它们转为可编辑摘要、引用或说明，再放入模块。

### 7.4 交付模块的可编辑性与边界

交付模块是**内容准备与叙事检查结构**，不是 Figma、Keynote 或专业排版工具的替代品。用户可在其中调整：

```text
模块顺序与内容分组
图片引用与裁切预览
标题、说明文字、图注
模块拆分 / 合并
缺口提示与素材清单
```

它可以保留非常轻的内容结构草图，帮助用户检查每一页或每一块是否讲清楚；但当前不承诺最终级网格、字体、字距、精细布局、可编辑 PPTX 或 Figma 级图层编辑。

尝试完全不同的叙事或整体内容结构时，复制模块在旁边试；不建立复杂的交付版本管理系统。最终精细排版与正式演示文件由 Figma 等外部工具完成。

## 8. 来源、版本、关联与决定

### 8.1 关系默认隐藏

Morpho 必须可追溯，但不能把画布变成蜘蛛网。关系线默认不显示；用户主动打开底部详情中的相关页签时，才在画布上临时显示直接关系。

### 8.2 一层关系查看

| 页签 | 查看什么 |
|---|---|
| 来源 | 直接上游资料、起始图、来源文档或用户说明 |
| 版本 | 直接父版本、当前对象、直接子版本 |
| 关联 | 直接被哪里使用：设计定义、方向、锚点、交付模块或阶段记录 |
| 决策 | 与对象直接相关的保留、淘汰、锁定或替换理由 |

不默认展开多层链路，不生成全项目关系图。

### 8.3 临时关系线

选择对象、打开详情或执行可追溯操作时，系统可短暂显示来源、版本或关联线；用户关闭详情、切换对象或点击空白后自动收起。

## 9. Undo / Redo

Undo / Redo 服务于用户可见、可明确撤销的手动操作。

### 9.1 不进入 Undo / Redo

```text
画布平移
缩放
视图定位
AI 新建分析、方向、图像、交付草稿或其他生成结果
AI 批量生成结果
```

AI 生成内容如果不需要，用户通过删除、状态调整或继续发展处理；不把“撤销”误当成 AI 重新理解项目或重跑模型的机制。

### 9.2 进入 Undo / Redo

```text
手动移动、缩放、裁切、分层
文本编辑
删除
组合 / 解散组合
隐藏 / 恢复
锁定 / 解锁
手动状态改变
交付模块布局与文字编辑
其他明确的人工画布结构操作
```

撤销返回的是前一个可见结构状态；它不触发模型重新阅读项目，也不改变用户未明确改变的项目理解。

## 10. 本文件不锁定的事项

以下问题留到后续视觉系统或技术方案，不在当前产品规则中假定：

- 画布具体视觉风格、栅格、缩放手感、缩略图尺寸与动画；
- 是否提供迷你地图、辅助对齐线、快捷键完整表；
- 长文档、超大图、视频或 3D 文件的精确预览方式；
- 多人同时编辑、评论、权限与冲突处理；
- 关系线的精确视觉规范；
- 运行时对象 ID、数据字段、存储和同步实现。

本文件锁定的是用户可见的空间语义、对象行为、操作边界和可追溯原则。

## 11. M4.1-B 已落地的对象边界

- 图片角色运行时只使用正式枚举：reference、preview、conceptImage、primaryVisual、sceneVisual、cmfStudy、detailStudy、structureDiagram、interactionDiagram、deliveryAsset。旧 main、scenario、cmf、detail、diagram 只作为旧数据迁移输入出现。
- VisualBranch 不是 MorphoObject，不生成画布卡片，不独立隐藏或删除，不直接进入交付引用。它只作为方向内图片聚合、视觉发展路线和视觉 Context 优先级记录。
- 归档 VisualBranch 只让分支退出默认视觉聚合和可选列表；不会删除图片、清空图片 directionId、破坏版本关系、来源关系或默认参考。
- 图片加入视觉分支时必须属于同一方向；无方向图片可以被明确加入该方向并获得 directionId + visualBranchId；跨方向加入必须阻止。
- 从带 directionId + visualBranchId 的图片继续生成时，新图继承方向与分支。来自不同方向的多张图不能让系统自动猜目标方向。
