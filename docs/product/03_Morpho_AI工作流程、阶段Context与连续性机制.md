# Morpho v3.2：AI 工作流程、连续会话与 Context 机制

> **文档角色**：规定 Morpho 的右侧 Agent 如何在一个连续项目会话中工作，以及系统如何在不打断用户的前提下管理任务策略、Token Budget、自动压缩、项目理解和资料读取。
> **配套阅读**：状态、版本、项目记忆与阶段记录见《04_Morpho_状态、版本、项目记录与记忆.md》；画布对象和操作见《02_Morpho_工作台、画布与对象规则.md》。  
> **继承说明**：本文件保留 v1 中“不同任务重点 / 自动压缩 / Handoff 接力”的职责，但明确替换按阶段、lane、选择对象或方向切断聊天历史的旧理解。详细来源与替换关系见《00_Morpho_v3_规则继承、覆盖与完整性账本.md》。

> **v3.1 原型前更新（2026-06-22）**：将“阶段”进一步收回为 AI 的内部 Context 组织；新增确定性下一步建议、对象选择建议、连续视觉发展和任务中断恢复规则。

> **v3.2 AI 连续性更新（2026-07-13）**：正式运行时收口为一个 Agent、一个连续项目会话、Token 驱动自动压缩、来源驱动 Memory Kernel、统一 Prompt Registry 和 Task Strategy Resolver。lane 降级为检索与分析标签，不再隔离正式请求历史。

## 1. 总原则：一个项目、一个连续 Agent 会话

用户从项目开始到交付，始终看到：

```text
同一个项目窗口
+ 同一张连续画布
+ 同一个右侧聊天
```

用户不会看到，也不实际存在按阶段拆开的正式聊天。右侧聊天始终连续；用户可以在方向与视觉发展时点回一张调研图，也不会失去此前未压缩对话或被强制带回调研模式。

系统仍按任务组织不同判断重点和资料，但不通过提前裁剪聊天来控制 Context。未压缩历史在有效 Token Budget 内完整携带；接近模型有效上下文上限时才自动压缩。图片像素、文档正文、全量对象和历史版本仍按任务需要读取，避免把无关大型资料塞进每一轮。

因此，Morpho 的规则是：

```text
用户层：连续项目、连续画布、连续 Agent 会话。
系统层：Task Strategy + Token Budget + 当前有效记录 + 版本化压缩摘要 + 按需资料。
```

阶段是任务策略、画布地标和阶段记录归类，不是聊天边界、用户必须逐格完成的任务清单或项目完成度。用户可以跳过前面阶段，直接从已有草图、旧渲染、成熟方案或交付准备开始。

## 2. 当前工作重点与逻辑阶段

### 2.1 六类阶段语义

Morpho 保留六类可能出现的内部 Context / 阶段记录：

```text
01 开始与输入
02 探索（可选）
03 调研
04 设计定义
05 方向与视觉发展
06 交付准备
```

这六类阶段语义为 Agent 提供不同判断重点，并为 Stage Record 归类；用户不需要手动切换，也不必按顺序走完。它们不决定压缩范围，不创建独立 Thread，也不能让压缩边界后的其他阶段聊天消失。

- 用户从空白开始，通常会经过开始与输入；
- 探索只在用户尚无稳定切入点时出现；
- 已有成熟方案的用户可以直接进入方向与视觉发展或交付准备；
- 未实际使用、未产生有效结果的 Context 不应生成空记录。

“预览、主图、场景、角度、CMF、细节、设计示意”是视觉对象的角色与生成意图，不再分别构成用户必须跨越的阶段门槛。

### 2.2 Compare 不是独立阶段

Compare 是任意 Context 中可发起的局部比较操作，不是固定区域、独立 Thread、独立阶段记录或项目必须经过的一步。

比较后真正做出的决定写回它服务的记录：

```text
比较研究资料
→ 写入“调研”记录

比较方向、预览、主图、场景或 CMF
→ 写入“方向与视觉发展”记录

比较展板结构 / 交付模块
→ 写入“交付准备”记录
```

### 2.3 当前工作重点来自用户正在推进的任务，不由点击位置决定

用户此刻正在和 AI 推进什么，决定当前内部 Context 应以什么重点理解任务。它来自用户的自然语言、明确要求和连续工作内容；不是一个需要用户手动操作的前台状态。

单次点击、框选、拖动或导航定位不会机械切换工作重点。例如用户正在发展一张方案图时点回调研图，调研图只是当前聊天的输入之一；只有用户明确要求重新分析、修订结论或回头做调研，系统才以调研的任务目标组织 Context。

### 2.4 确定性成果规则只准备下一步建议，不判断“是否完成”

系统不依赖模型持续监控用户是否看完、是否满意或某阶段是否“够了”。当出现确定性成果时，例如研究与分析已创建、若干关键结论被保留、设计定义被应用、方向被创建或交付模块开始出现，系统可以按规则准备一组下一步建议。

这些建议不会在结果刚出现时立即打断用户。它们在用户下一次聚焦输入框、主动展开建议或准备继续操作时轻量显示。用户可继续当前工作、采用建议、忽略或关闭；系统不因此自动切换 Context，也不宣告阶段完成。

### 2.5 选择建议服务发现性，不等于 AI 自动判断

用户选中对象后，系统根据对象类型、数量和直接关系给出少量建议。点击建议只将一句可编辑指令填入输入框；用户仍决定是否发送、如何修改、是否执行。选择建议不要求模型后台运行，也不替用户猜测当前意图。

## 3. Agent 的完整 Context 合同

每轮正式 Agent 输入按以下顺序组装：

```text
核心 Agent 规则
+ 当前任务策略块
+ 当前有效项目记忆的紧凑投影
+ 当前相关阶段记录
+ 上一次压缩摘要（若存在）
+ 压缩边界之后的完整连续聊天
+ 当前明确选择 / 指定的对象和必要资料
+ 当前图像像素或文档正文（仅在任务需要时）
+ 当前用户输入
```

这是一份逻辑输入合同。聊天连续性默认完整；大型对象、图片像素、文档正文、旧版本和历史来源仍按任务相关性读取。

### 3.1 信息优先级

```text
当前用户明确输入
> 当前真实结构化项目状态
> 已确认的项目记忆与阶段记录
> 当前未压缩对话
> 压缩摘要
> AI 旧建议和未确认草案
```

摘要不能覆盖当前事实，AI 旧建议不能升级为用户决定，默认参考不能覆盖用户本轮明确选择。

### 3.2 Token Budget 组装

正式 Context Builder 不按固定消息数裁剪。每轮预算至少考虑：

```text
系统与工具 Schema 成本
+ 项目记忆和阶段记录成本
+ 当前任务对象成本
+ 图片与文档成本
+ 压缩摘要成本
+ 压缩边界后的连续历史成本
+ 当前输入
+ 输出与后续工具调用预留
```

真实 Provider usage 优先于估算；没有 usage 时使用同一套保守估算。`normal / prepare / compact / emergency` 是内部压力状态，不作为用户可见进度。

Morpho 的生产 Context Policy 固定为：`windowTokens = 256000`、`prepareTokens = 204800`、`compactTokens = 230400`、`targetUncompressedTokens = 16000`。这是 Morpho 自己认可的内部预算，不代表 Provider 的物理上限，也不接受 Vercel 或 Provider 环境变量在生产中改写。`prepare` 只做准备；达到 90% 的 `compact` 才生成并持久化摘要。客户端压缩、服务端 Agent Budget 和图像/工具预留都从 `src/domain/morpho/agentContextPolicy.ts` 的同一策略出发。

### 3.3 “默认不读取全部历史”的准确含义

- 尚未压缩的聊天默认完整携带；
- 已压缩的早期聊天默认通过当前摘要修订携带；
- 当前项目记忆的有界紧凑内容每轮默认携带，包括项目概览、设计定义、稳定偏好、待确认问题和任务相关的当前阶段记录；
- 原始聊天始终持久化保留；
- 用户追问具体旧内容时，通过确定性聊天查询读取原始消息；
- 不默认读取的是全画布、全部图片像素、所有文档正文、所有历史版本、全部隐藏内容和无关淘汰方向。

隐藏内容只有在用户恢复、明确指定或当前授权来源直接依赖时才可进入任务范围。

### 3.4 Prompt Registry 与任务策略

正式 Agent 只有一套版本化 Prompt Registry。核心规则与 `discussion / research / designDefinition / conceptDirection / directionPreview / visualDevelopment / comparison / deliveryPreparation / historyAndMemory` 等任务策略块按需组合。阶段只是解析依据之一，不做强制路由。

每轮记录 `promptContractVersion`。任何写入都只能通过本地工具提交，未确认 Proposal 不等于项目事实；历史、项目记忆或阶段记录问题必须先读取真实来源。

## 4. 连续会话与自动压缩生命周期

### 4.1 正常连续工作

Agent 可以跨阶段反复分析、生成、比较、修改与讨论。切换当前重点、选择对象、方向、VisualBranch、画布区域或交付准备，只调整任务策略和资料选择；它们不推进压缩边界，也不让此前未压缩聊天消失。

### 4.2 自动压缩触发与顺序

系统以真实输入 Token 压力为准，不以固定消息数、字符数、阶段切换或方向切换触发。流程为：

```text
估算真实输入 Token 压力
→ 接近安全阈值时进入 prepare
→ 先提交本轮确定性状态变化
→ 处理用户明确的长期偏好、约束、决定与淘汰理由
→ 更新受影响阶段记录
→ 进入 compact 时生成高保真摘要修订
→ 记录覆盖的消息起止 ID、数量和摘要版本
→ 后续携带摘要 + 边界后的完整消息
→ 原始消息继续保留
```

`prepare` 只准备稳定记录，不丢消息；`compact` 才推进边界；Provider 明确返回 context overflow 时，可进入一次 `emergency` 压缩重试。压缩失败、记忆更新失败或摘要校验失败时，不推进边界、不删除原始消息、不把半成品当成成功，也不撤销已经完成的 Agent 回复和项目写入。

### 4.3 压缩状态和摘要修订

运行时必须持久化当前摘要修订、上一修订、覆盖消息边界、覆盖数量、估算输入 Token 和来源消息哈希或等价信息，以便：

- 后续只携带摘要和边界后的完整历史；
- 判断摘要是否过期；
- 避免重复压缩同一段；
- 从旧 checkpoint 迁移；
- 备份恢复后继续而不重复压缩。

摘要包含线程目标、已建立上下文、决定与理由、当前工作、未解问题、引用对象和下一回合锚点；它不是项目事实源，也不能覆盖真实状态。

### 4.4 手动 `/compact`

`/compact` 只作为调试和手动补救。它按同一项目连续会话和当前压缩边界整理，不按 lane 分块；不创建或修改画布对象，不切换工作重点，也不要求用户日常管理 Context。其命令和纯状态消息标记为 `contextVisibility=uiOnly`：可以显示、备份和审计，但不进入模型 Context、摘要或普通历史搜索。只有全部摘要写入成功才推进边界。

### 4.5 历史、记忆和阶段记录查询

用户询问“最早的对话”“第一次提到某方向”“以前为什么淘汰”“项目记忆、阶段记录和进度”时，Agent 必须先调用真实读取能力：

```text
search_project_conversation
read_project_memory
read_stage_record
```

聊天查询至少支持 earliest / latest、关键词、role、时间范围和有限相邻上下文，并返回 messageId 与时间。读取工具返回当前修订、紧凑正文、来源摘要、`reviewRequired` 和截断信息。未读取前不得根据当前狭窄 Context 宣称“没有”“不存在”或“未记录”。

### 4.6 回头修改早期内容

用户明确回到早期内容时，系统：

1. 使用当前有效项目记忆、相关早期阶段记录、指定对象和最新输入继续；
2. 修改对应的早期对象、结论、设计定义或方向状态；
3. 更新受影响阶段记录的当前有效版本；
4. 仅提示下游内容可能需要复核，不自动推翻、删除或替换后续成果。

### 4.7 跨阶段多选

跨阶段多选不触发复杂强制分类流程。AI 根据当前工作重点、选中对象、邻近画布内容和用户的话理解任务。

只有对象差异很大、且用户没有说明想做什么时，才问一个真正有价值的问题，例如：

> 你想比较它们是否支持同一条项目方向，还是想找这些资料之间的共同线索？

## 5. AI 的三类输出与执行边界

### 5.0 任务模式与 Operation 边界

正式 AI 面板只使用一套 Agent Runtime：

```text
/api/ai/agent
+ Responses 流式协议
+ Function Tools
+ 一个 Context Builder
+ 一个 Memory Kernel
+ 一个 Confirmation Policy
```

交付章节草稿、设计定义、概念方向、比较、研究、图像计划和受控记忆更新都通过 Agent 工具或共享领域服务完成。旧 `/api/ai/chat` 不再作为正式面板的分流路径；若为旧备份或测试保留兼容路由，也不得拥有另一套会与 Agent 冲突的 System Prompt、流协议或写入合同。

发送消息时，用户手动选择的 `taskMode` 是最高优先级执行依据；当界面仍处于默认对话状态、用户没有显式覆盖时，正则判断、当前选择对象和建议 chip 可以把自然语言请求路由到研究、图像生成或语义 Proposal 任务。推荐只在发送时影响本次执行，不得在用户确认前直接改写项目对象、默认参考、方向状态或交付内容。

当前用户可见任务模式保持三类：

```text
对话与分析
图像生成
研究任务
```

`workIntent` 是 `对话与分析` 内部的当前工作目标，用于决定 Context、系统提示和 Proposal 类型。recommendedWorkIntent 只能提示；用户发送时以当前显式选择的 workIntent 为准，不因关键词正则静默覆盖。

研究、图像生成、设计定义草案和概念方向草案进入受控 Operation Runtime。真正调用 Provider 且可能生成 Proposal 或图片的任务统一经过 active Operation gate：researchOperation、imageGeneration、createDesignDefinition、reviseDesignDefinition、createConceptDirections、reviseConceptDirection、splitConceptDirection、mergeConceptDirections。已有 queued / preparing / running / waiting_for_user Operation 时，新任务必须阻止并说明当前任务，不能静默并行提交。

普通 discussion / comparison 仍可作为轻量连续聊天；它们不因选中方向或推荐意图自动生成 Proposal。模型只能围绕当前任务和证据缺口调用工具，不得无意义重复搜索、无限扩展任务范围或直接改写项目对象。

Proposal reviewState 的应用行为必须区分：

```text
ready：可直接应用
sourceChanged：显示具体来源变化，用户确认已复核后才能应用
baseSuperseded：禁止直接应用，可基于当前版本重新生成
targetUnavailable：禁止直接应用，可继续讨论、复制内容、重新生成或放弃
```

### 5.1 三类输出

| 类型 | 适用情况 | 系统行为 |
|---|---|---|
| **只回答** | 普通讨论、解释、分析、建议 | 正文留在聊天；不创建对象、不改状态。若本轮包含用户明确的稳定偏好、约束或决定理由，可通过受控工具单独提交来源完整的局部记忆更新；不能从 AI 自己的建议推断写入。 |
| **提议可执行动作** | 需要说明范围、处于先确认模式、影响较大 | 在聊天中给确认卡；确认前不创建或改变项目 |
| **执行并放置结果** | 用户意图明确，且操作低影响或处于自动执行模式 | 创建结果并放到相关画布位置；保留必要来源与关系 |

### 5.2 自动执行与先确认

输入框旁的模式只影响创建、修改、生成、整理和执行动作；不影响普通聊天、分析或解释。

**自动执行**适用于用户意图清楚、影响较低的工作，例如：

- 分析已选资料；
- 创建研究与分析；
- 生成方向预览；
- 继续发展选中图像；
- 生成指定的角度、场景、CMF、细节或示意；
- 整理短文字或创建低影响的草稿。

**先确认**时，AI 先给出可执行动作说明，用户确认后再执行。

### 5.3 无论模式如何，都必须来自用户明确决定的事项

以下事项不能由 AI 自行决定：

```text
应用或替换当前设计定义
设为主方向、备选或已淘汰
锁定或替换主视觉锚点
写入当前有效项目记忆中的稳定事实
确认重要交付结构
批量 / 高影响删除、替换、改状态或改引用
```

用户明确点击对应按钮，或说出明确自然语言指令，即视为确认；系统不应再额外问一次“你确定吗”。

### 5.4 确认卡

确认卡嵌在右侧连续聊天里，不是弹窗，不遮挡画布，也不阻塞继续聊天。

卡片只说明四件事：

```text
要做什么？
基于什么？
会得到 / 改变什么？
不会影响什么？
```

不默认展示完整 Prompt、模型参数、采样步骤或技术配置。

确认卡创建后绑定当时的对象和范围。之后用户选了其他图，旧卡不能悄悄换目标；若条件已变化，应提示“当前条件已变化，需要重新确认”。

### 5.5 高影响操作

无论自动执行还是先确认，以下操作都必须清楚呈现范围：

- 大批量生成；
- 批量删除；
- 批量替换；
- 批量状态修改；
- 多个交付模块引用更新；
- 可能令用户误以为旧内容失效的结构修改。

### 5.6 任务中断、失败与不可读输入

生成、分析、提取或编辑失败时，状态只在任务发生处与轻量活动提示中出现；不弹全屏错误页，不建立常驻任务中心。系统必须保留原对象、原选择范围和已输入但未完成的要求。

用户可按情况选择：

```text
重试
修改后重试
取消并保留原对象
```

取消不删除来源图、输入或已有结果。文件或链接不可读时，系统明确说明“当前未读取到内容”，不假装分析成功；可提供上传截图、粘贴文字、换一个文件或保留链接作为来源等替代路径。具体文件解析与网络失败实现留给技术方案。

Operation 中断或刷新后，不得假装任务仍在后台运行。系统保留输入快照、已完成步骤和已取得引用，将未完成任务标记为“已中断”，等待用户明确重试或取消。

Provider 视觉输入和 web search 都必须以兼容协议和真实验证为准。当前实现中，正式 Agent 可发送显式选中的 active 图片像素；图片较多时系统可自动生成总览图覆盖全部选中资料，不向用户暴露图片数量限制，也不静默丢弃参考。隐藏图片、未选旧图和整张画布不默认进入输入。

当 `MORPHO_AI_WEB_SEARCH_ENABLED=true` 时，符合条件的 Agent tool profile 可向 OpenAI-compatible provider 提供 web-search 工具，由模型判断是否需要联网验证、补充案例、查找当前信息或提供外部来源。普通创意发散、文字改写和不依赖外部事实的视觉讨论不应主动联网。图像生成永不启用 web search。

受控 Agent 的单次回合不设置累计联网搜索次数上限。搜索是否继续由任务需要和证据充分程度决定；用户要求全面、广泛或多角度调研时，可以拆分不同查询、核对来源并针对缺口继续检索。单次本地搜索结果仍保持合理体积，跨搜索来源按 URL 和内容去重，较早工具结果继续由 Context 机制压缩。连续相同工具与等价参数仍会触发循环保护，不同关键词或不同角度不得被误判为重复。

聊天、ResearchAnalysisProposal 和正式 ResearchObject 只能展示 provider 返回的真实 citation snapshot；不得从普通模型文本里猜测或伪造来源。

通过结构、字段、来源与参考校验的 Agent 图像计划按用户请求执行；单次 Agent 回合不设置累计图片数量确认门槛，图片数量本身也不是请求确认的理由。图片生成仍受 Provider 真实配额、API 参数校验、并发控制、pending slot、逐项写回、失败隔离和用户取消约束，且每张结果都创建新对象，不覆盖原图。自动执行/先确认模式、用户主动确认以及其他高影响项目决定的确认语义保持不变。

内部 28 个模型回合、18 分钟总时长和等价工具重复检测只是异常恢复保护，不是产品步骤或可见进度。触发保护后停止继续调用工具，保留已有过程、引用、图片和项目写入，并用一次无工具请求整理已完成内容与未完成部分。

## 6. 逐阶段 AI 工作规则

### 6.1 开始与输入

**目标**：接收用户的初始想法、文件、图片、链接、旧项目资料或空白状态，建立项目起点，但不在信息不足时假装已经理解整个项目。

#### 空白项目

用户可以直接说：

```text
我想做一个……
我只有一个大概方向……
我不知道做什么……
```

AI 先用少量自然问题帮助用户开始，例如了解对象、场景、课程 / 比赛约束或用户想先探索还是直接调研。不要要求用户填写完整 Brief 表单。

#### 已导入资料

AI 只理解用户选中或明确说明的资料。用户可自然说：

> 前五张是竞品，右边两张是用户真实场景，PDF 是课程要求。

这种说明是当前任务的来源语境；系统不因此强迫为每一张原始资料永久打上“竞品”“场景”等标签。

#### 项目起点概览

当项目起点已有足够明确的内容，AI 可在聊天中形成简短起点概览，供用户确认或继续补充。只有用户明确确认的基础信息才进入当前有效项目记忆。

### 6.2 探索（可选）

**适用情况**：用户只有宽泛主题、想法混乱或不确定从哪切入。

探索不是产品名清单，也不是一口气抛出十几个概念。AI 先从用户的场景、对象、兴趣、约束或课题里提出少量有真实差异的切入方向，帮助用户判断：

```text
做什么对象
解决哪个切口
为什么值得继续
适合怎样的 ID 外观概念表达
```

先在聊天中讨论草案。只有用户明确要保留、比较或继续验证的内容，才成为画布对象。用户自提方向同样可直接进入后续调研。

当出现 1–3 条值得验证的方向、用户希望继续验证，或继续发散收益明显变低时，AI 轻建议：

```text
进入调研 / 继续探索
```

### 6.3 调研

**目标**：把用户指定的资料、情境、竞品、参考图和文档转化为候选发现、设计机会、现实约束与待验证问题；不把分析直接伪装成项目事实。

#### 发起

正常起点是用户选中一批资料并说“分析这些”，或点击“研究与分析”。AI 只基于当前选中对象、当时补充说明和任务相关 Context 工作，不默认分析整张调研画布。

#### 研究与分析对象

用户明确发起后，AI 可以创建研究与分析对象。内容包含候选：

```text
发现
设计机会
现实约束
待验证
```

它们都只是候选。AI 可推荐保留，并说明依据和证据不足之处；用户确认后，才创建独立关键结论对象。

#### 调研阶段不擅自做什么

不自动：

- 生成设计定义；
- 生成概念方向；
- 写入项目记忆；
- 把结论标为已确认；
- 重排整张画布；
- 把全画布资料写成长报告；
- 因发现一个机会就直接生图。

### 6.4 设计定义

**目标**：把已确认发现收束成后续方向共同遵循的前提，同时清楚保留尚未决定的内容。

设计定义回答：

```text
解决什么问题？
谁在什么场景遇到？
要达到什么？
必须遵守什么？
要避免什么？
哪些仍待确认？
```

它不提前规定最终产品一定长什么样、一定使用何种结构、材料、尺寸、配色、构图或 Prompt。

#### 生成草稿

用户选中关键结论后点“整理为设计定义”时，AI 优先基于这些结论生成草稿。用户未选时，AI 只使用当前项目中已确认且仍有效的关键结论，不重新塞入已替代、已否定或只属于淘汰方向的内容。

草稿可讨论和调整，但在用户点“设为当前设计定义”前：

- 不成为后续方向生成的默认依据；
- 不写入当前有效项目记忆；
- 不自动改变已有方向或主图。

#### 当前有效定义与修订

用户明确应用后，系统更新当前有效设计定义、相关阶段记录、项目记忆、结构化状态和后续默认依据。应用后出现实质修改时，先形成修订草稿；用户明确应用后才替换当前有效版本。

### 6.5 方向与视觉发展

**目标**：让用户形成真正不同的概念方向，并在同一个连续视觉工作区中自由判断、发展、修改和衍生图像。方向、预览、主图和各类素材之间可以互相回流，不做硬性门槛。

#### 概念方向与初步预览

方向应在真正影响设计判断的层面不同，例如：

```text
产品架构
核心部件关系
形态语言
与空间 / 人体关系
使用机制
比例与体量
```

不能只换颜色、背景、灯光、视角或几句形容词。

用户可选中方向并点击“生成预览”，或自然说“给这个方向出几张看看”。通常使用：

```text
当前有效设计定义
+ 当前方向策略与关键词
+ 用户明确选中的参考图或补充说明
```

方向预览默认 4 张，界面可提供 2 / 4 / 6 快捷项。它用于快速判断产品形态、视觉气质与可继续性，不自动设主方向、默认参考或淘汰其他方向。快捷项不是能力上限；用户明确要求其他合理数量时按原要求计划和执行。

方向 Proposal 的应用意图必须明确：

```text
create：创建一个或多个新方向，revision 1，status = pendingPreview，不自动设为主方向
revise：复用一个目标 directionId，创建 revision +1，保留原方向下图片与 VisualBranch
split：从一个父方向拆出两个或更多新方向，写 splitFromDirection lineage，父方向不自动淘汰
merge：把两个或更多父方向合成一个新方向，对每个父方向写 mergedFromDirection lineage，父方向不自动淘汰
```

#### 任意图都可继续发展或衍生表达

从第一张预览图开始，用户选中任意图都可以提出：

```text
继续发展
定向修改
生成其他角度
生成使用场景
生成 CMF / 配色
生成关键细节
生成设计示意
作为多参考生成
用于交付
```

这些是生成意图，不是不同阶段的专属权限。用户可以从预览图直接探索场景，也可以从场景图反过来发展主图；系统只根据当前选中的图、用户意图、项目记忆和相关记录组织本次生成。

#### 主图与后续默认参考

“主图”是用户希望重点收束的一条视觉路线中的核心结果，不是其他操作的前置条件。用户想把一条路线做稳时，AI 默认保持已成立的核心轮廓、比例和部件关系，只改用户明确指出的问题。

用户可把某张图设为**后续默认参考**（内部状态仍称主视觉锚点）：之后相关生成默认继承其产品架构、比例与体量、关键部件关系、CMF 基线和视觉语言。没有设定时，当前选中的图就是本次生成的参考；设定默认参考不会限制用户从其他图继续发展。

#### 正常发展、分支与数量

材料、颜色、背景、视角、局部比例和局部部件调整，通常属于同一路线的继续。只有产品架构、核心使用机制或整体产品类型改变时，才创建新视觉分支；原路线保留，不自动改变主方向、设计定义、默认参考或交付内容。

默认生成数量保持轻量，表中数字只用于快捷选择：

| 任务 | 默认 | 可选 |
|---|---:|---:|
| 方向预览、整体继续发展 | 4 张 | 2 / 4 / 6 |
| 定向修改 | 2 张 | 1 / 2 / 4 |
| 角度、场景、CMF、细节、示意等衍生表达 | 2 张 | 1 / 2 / 4 |

用户自然语言中的“来一张”“生成 3 / 5 / 9 / 12 张”“四个方向各 3 张”等明确要求优先于默认值。Agent 一次形成完整计划，执行层可依据 Provider 真实限制、账户配额和并发上限透明分批；不得以旧总数 8、方向最多 3 或预设 enum 拒绝，也不因数量额外要求确认。每轮结果在来源图附近以合集出现，并保留简短修改 / 生成意图摘要；完整 Prompt 在来源详情中可追溯，但不堆在画布卡片上。

#### 结构化视觉计划与 Prompt 编译

Agent 先为每个结果形成结构化视觉意图，至少区分：目的与图片角色、目标方向和分支、用户明确参考、改变目标、必须保留、允许变化、构图与视角、产品形态、CMF、场景与光线、避免项。Morpho 再确定性解析参考图，并结合当前 Design Brief、Direction Revision、User Preferences、图片角色和目标模型适配器编译最终 Provider Prompt。

参考优先级为：本轮显式参考 > 当前选中来源图 > 当前视觉分支根图或直接父图 > 目标方向代表图 > 适用时的后续默认参考 > 其他必要项目参考。用户明确说“不参考默认图”时必须排除；多方向按目标项分别解析；Provider 参考上限按优先级裁剪并记录省略项，不让模型随机丢图。结构化意图、编译 Prompt、解析后的参考、模型参数和 Provider task id 都写入 Generation Record。

### 6.6 Compare 比较操作

**目标**：帮助用户看清候选之间的差异、适用性、风险和可借用局部，不假装替用户做决定。

用户选中两个或更多对象后点击 Compare，或直接说“比较这些”。仅框选不自动发起 Compare。

默认分析：

```text
主要差异
各自更适合解决什么
与当前设计定义的匹配
风险 / 不确定性
值得保留的局部
```

AI 根据对象类型临时选择比较维度：多个方向看策略、架构和后续空间；多张图看形态、比例、部件关系和视觉潜力；CMF 看材质、色彩和气质；文档看前提变化和可能影响；图文混合看策略是否被视觉真正表达。

默认比较分析只留在聊天，画布只显示临时焦点。用户明确点“保留比较记录”才创建简洁比较对象。AI 不自动写主方向、淘汰状态或项目记忆。

### 6.7 交付准备

**目标**：依据用户真正要交的内容，把已有过程和素材组织成可带去 Figma 等工具完成最终排版的交付准备包；先解决叙事与缺口，再决定是否需要生成新图。

交付区域始终可用；只有用户明确开始准备某种输出时，交付准备才成为当前 Context 的重点。

用户未说明输出目标时，AI 最多问一句：

> 这次主要准备展板、PPT、作品集，还是素材整理？

AI 先在聊天中给简短交付计划草案；用户确认或调整后，再创建页面 / 模块结构。它整理的内容包括：

```text
交付叙事结构
逐页 / 逐模块标题、正文、图注和说明
已选图片与来源
明确缺口与素材清单
可选的展板 / 页面视觉参考图
```

处理缺口顺序：

```text
先复用已有内容
→ 再补说明 / 重组文字 / 调整内容结构
→ 最后才建议生成新图
```

当前不承诺完成最终展板精细排版、可编辑 PPTX、完整 PPT 版式编辑或 Figma 级图层能力。用户带走的是可继续排版的内容与素材准备包，而不是半成品专业排版文件。

## 7. 图像定向编辑、局部借用与说明标注

### 7.1 四种不同操作

单张图可执行：

```text
继续发展
定向修改
衍生表达
保留局部
添加说明标注
```

它们不能混成一个“画圈生图”工具，也不由图像当前角色限制。预览图、主图、场景图或旧图都可以使用这些操作。

| 操作 | 含义 | 结果 |
|---|---|---|
| 继续发展 | 整体继续迭代 | 新一轮整图变体 |
| 定向修改 | 改指定部位，尽量保持其他部分 | 新的定向修改版本 |
| 衍生表达 | 以当前图为参考生成角度、场景、CMF、细节、示意或展示图 | 新的视觉对象或合集 |
| 保留局部 | 留下结构、材质、比例或连接逻辑供后续借用 | 记录局部来源关系 |
| 添加说明标注 | 留下供自己或交付使用的图上解释 | 可编辑长期说明层 |

### 7.2 定向修改

流程：

```text
选中一张图
→ 点击“定向修改”
→ 圈选、划线或箭头标出区域
→ 输入自然语言要求
→ 生成新结果
```

圈选表示“优先改这里，并尽量保留圈外已成立部分”，不是 Photoshop 式像素级绝对锁定。当前 GrsAI 请求没有 mask/inpainting 参数，因此这是基于参考图和提示词的定向修改，不是真正的蒙版局部编辑。定向修改默认 2 张；用户可明确指定其他数量。

若要求实际改变整体架构或核心逻辑，应生成新视觉分支，不伪装成小修。

### 7.3 保留局部与借用局部

保留局部默认记录：

```text
来源对象
+ 局部位置
+ 用户说要保留的逻辑
+ 后续被用到哪里
```

不自动裁出大量碎图。用户明确点“提取为局部参考”时，才创建裁切后的局部参考对象。

借用局部时，来源和目标必须明确。结果是目标图的新版本；来源图不变，并建立借用关系。

### 7.4 编辑标注与说明标注

**编辑标注**是给当前 AI 任务看的临时圈、箭头、涂抹和要求：生成前可见，生成后不默认覆盖原图，保存在版本详情中供追溯。

**说明标注**是用户希望长期留在画布或交付中的解释层：可包含圈选、箭头、短文字、简单手绘线和编号。它不修改原图，默认随图移动缩放，也可单独编辑、隐藏、删除或用于交付。

### 7.5 外部图片

用户导入的草图、旧渲染、截图、竞品图、网页图和文档提取图都可被讨论、圈选、作为局部参考，并生成新的项目内设计版本。系统不修改用户硬盘里的原文件。

第一阶段不做复杂多图批量局部修图。多图可以 Compare、组合、讨论或作为多参考输入，但不直接做多图批量局部编辑。
