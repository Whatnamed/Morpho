## 1. 一条完整的资料生命周期

Morpho 不把资料处理做成单独的“文件管理流程”。用户最常见的路径应当是：

```text
首页找到或新建项目
→ 直接拖入 / 粘贴资料或开始聊天
→ 在画布中使用资料
→ 需要时从资产或搜索快速找回
→ 把已有内容稳定引用进交付模块
→ 导出成果、归档项目或恢复到新项目副本
```

首页、资产库、搜索、导入和归档都服务这一条路径：让材料进入项目、留在可追溯关系里、随时找回并在结束时带走。

## 2. 项目首页

### 2.1 首页只做四件事

首页默认提供：

```text
新建项目
继续最近项目
搜索项目
恢复项目备份
```

它不是项目管理后台，因此不显示：

```text
项目进度百分比
任务数量
阶段完成条
团队动态
日历
资源看板
```

用户最常见的行为是继续最近项目，所以默认按最近打开排序；另提供“按最近更新”和“按名称”两种排序选项。

首页的当前形态（2026-07-27 定稿）是一个工作区外壳：左侧栏承载品牌、工作区名、
“恢复项目备份”、账户入口（含测试状态与当日额度；本地模式下显示“本地模式 ·
未连接账户”），以及若干标注“规划中”的占位入口（灵感资料、个人草稿、已归档项目、
设置、帮助）。规划中占位只是界面预留，不构成新的产品承诺，也不违反“首页只做
四件事”——四件事仍是首页唯一可用的功能。主区依次是“继续最近项目”大卡（含画布
对象/视觉素材计数与实时画布缩略图）和统一尺寸的项目网格。

### 2.2 项目卡

已有项目用简洁卡片呈现：

```text
项目封面
项目名称
一句课题 / 说明
最近工作重点
上次打开时间
```

“最近工作重点”只帮助用户回忆上次停在哪里，例如“方向与视觉发展”或“交付准备”；它不代表项目前面阶段已经完成，也不构成线性进度判断。

### 2.3 项目封面

封面优先级：

```text
用户手动设定的封面
→ 当前主视觉锚点
→ 当前主方向中最近持续发展的方案图
→ 简洁画布概览 / 空白项目占位
```

用户可以对任意合适的图片点“设为项目封面”。一旦用户手动设置，封面固定，不因锚点替换或新图生成自动跳变。

> 实现状态（2026-07-27）：当前实现为“简洁画布概览”——按对象真实几何实时渲染的
> 画布缩略图（空项目显示居中取景圈）。手动设定封面与主视觉锚点封面尚未实现，
> 上述优先级仍是目标规则。

### 2.4 新建项目

点击“新建项目”后直接进入空白工作台，不要求先填写项目名称、领域、交付物、Brief 或标签。用户可以：

```text
输入一句想法
直接在右侧聊天说明
粘贴图片
拖入文件
拖入 URL
从已有草图或旧渲染开始
```

项目名称可在实际形成起点后再补。

### 2.5 重开项目时保持退出状态

用户再次进入项目时，默认回到退出前的画布位置、缩放和主要界面展开状态；不强制弹出阶段总结、恢复向导或“是否继续下一阶段”的对话。聊天也保持原有连续位置。

系统仍会在后台使用项目记忆、阶段记录和当前对象状态维持理解，但不把这些内部信息强行展示给用户。用户可以直接继续聊天、继续拖动、选中旧对象或从任何位置重新开始工作。

### 2.5 项目搜索

首页搜索只搜索项目：

```text
项目名称
项目概览中的课题 / Brief
```

不把首页做成跨项目图片库或复杂知识库。用户要找“那个老人卫浴项目”，直接搜“卫浴”即可。

## 3. 项目内资产

### 3.1 资产库的角色

资产库不是第二张画布，不是用户必须整理的文件夹系统，也不把所有项目对象复制一遍。

它只解决一个实际问题：

> 画布很大、资料很多、某张图被折叠、拖远、隐藏或已经用于交付时，用户还能迅速找回来。

资产入口位于左侧展开栏，打开后从左侧出现可收起的资产面板，不离开当前画布。

### 3.2 什么进入资产库

进入资产库：

```text
原始导入的图片
原始导入的文件
原始导入的链接
AI 生成的图片
文档及用户提取出来的页面、图片或文字素材
```

不进入资产库：

```text
研究与分析
关键结论
设计定义
概念方向
普通文本、箭头、说明标注
阶段区域
组合
交付模块
```

这些属于项目过程对象，应在画布、详情或项目内搜索中找到，而不是在资产库里再造一套重复管理。

### 3.3 轻量筛选

资产面板默认只提供来源 / 类型筛选：

```text
全部
原始资料
生成结果
文档
已用于交付
```

这些筛选由系统根据来源识别；用户不必创建“竞品”“材质”“场景”“课程资料”等文件夹，也不必逐个改名或贴标签。

批量导入和批量生成的视觉内容在资产库中可保留批次关系，例如：

```text
课程参考图 · 12 张
方向 B · 第一轮预览 · 4 张
```

这只是帮助回找，不把合集变成永久语义分类。

### 3.4 资产与画布的位置关系

同一资产可以有多个画布实例，但资产库不把它们误显示为多个文件。

资产项的基本动作：

```text
定位
→ 跳到它当前已有的画布位置

拖到画布
→ 创建一个新的画布实例

查看使用位置
→ 查看它被引用到哪些交付模块
```

用户把同一张参考图再次拖到方向附近比较，不需要重新上传，也不影响原位置。

### 3.5 交付引用不制造新的资产副本

交付区中的图片是对源资产的稳定引用实例，不是新上传的一份资产。

资产库只保留源资产，并以轻量提示显示：

```text
已用于交付
```

用户可查看它出现在哪些交付模块，也可再拖出一个新的引用实例。源图后续移动、删除或出现新版本时，不会静默替换已放进交付的内容。

## 4. 项目内搜索与隐藏内容恢复

### 4.1 搜索的作用

项目内搜索是找东西，不是让用户先管理东西。它从顶部或左侧轻入口、也可通过常用快捷键打开；不常驻占用画布空间。

搜索范围包括：

```text
画布对象名称与可见文本
文件名
链接标题、域名和可读摘要
文档可读取内容
研究与分析、关键结论、设计定义、方向中的文字
图像和生成结果的系统描述
交付模块标题与说明
```

用户可以直接搜：

```text
低施工
扶手
课程要求
方向 B
用于展板的场景图
那张带木纹材质的参考图
```

不要求预先打标签。

### 4.2 搜索结果与动作

结果按实际类型轻量分组：

```text
画布内容
素材与文件
文档内容
交付引用
```

每个结果只提供必要动作：

```text
定位到画布
查看来源
查看版本
查看用于哪里
```

不提供默认全项目关系图，也不要求用户在搜索中先选择对象类别。

### 4.3 隐藏内容

隐藏不属于资产类型。左侧保留一个轻入口：

```text
画布内容
[全部] [已隐藏]
```

用户进入“已隐藏”后，可以看到隐藏对象的缩略图或名称，并执行：

```text
恢复到原位置
并定位到它
```

搜索可以找到隐藏内容，但结果会明确标记“已隐藏”。用户选择后，系统提供“恢复并定位”；AI 不会因为搜索或隐藏对象存在，就把它当作默认工作输入。

## 5. 导入与资料进入项目

### 5.1 四种直接输入

用户的直接输入规则：

```text
粘贴图片 → 图片对象
粘贴文字 → 文本对象
拖入文件 → 文件对象
拖入 URL → 链接对象
```

用户拖到哪里，内容就落在哪里；从顶部“导入”入口加入时，内容放在当前视野的空白处并自动聚焦。

导入行为不先弹出分类表单，也不要求说明“这是竞品、用户场景还是风格参考”。用户可以在聊天中自然补充说明，系统只在当前任务中使用这些语境。

### 5.2 批量导入视觉资料

一次拖入多张图片：

```text
多张图片
→ 一个合集
→ 初次展开并聚焦
→ 用户看完后自行决定折叠、拖出或解散
```

合集成员仍独立可选、比较、作为 AI 输入、继续发展、用于交付或删除。

### 5.3 混合导入

图片与文档一起导入时，不强行塞进同一个合集：

```text
多张图片 → 一个图片合集
PDF / PPT / Word 等 → 各自作为文件对象，放在合集旁
```

用户可以随后说明：

> 这批图片是竞品，PDF 是课程要求，右边两张是我之前的草图。

系统把这当作当前理解，不自动变成永久分类或记忆事实。

### 5.4 文档阅读与提取

文档导入后默认是一个文件对象，不会在导入瞬间拆成几十页铺满画布。

需要时，用户可：

```text
打开阅读
提取某一页
提取图片
提取文字
```

提取的页面、图片或文字才成为可独立拖放、搜索和复用的资产 / 画布对象；原文档与提取结果保持来源关系。

### 5.5 链接

URL 默认作为链接对象保留。系统不假定所有链接都能稳定抓取或长期可读；用户可在项目中保留它作为来源入口，必要时再提取可用内容或截图。

链接失效时，不自动“补造”原网页内容。已经提取或导入进项目的内容仍作为独立对象存在。

### 5.6 不可读文件与失效链接

文件、PDF、PPT、Word 或链接并不保证都能被稳定读取。无法读取时，系统必须明确说明当前内容未被解析或未被访问，不能把猜测伪装成分析结果。

用户可按情况选择：

```text
上传截图
粘贴可读文字
换一个文件或链接
保留当前链接作为来源入口
```

已提取进项目的页面、图片或文字仍作为独立对象保留；链接后来失效时，系统不补造原网页内容。

### 5.6 旧资料与已有项目内容

以前的图片、PDF、PPT、草图、旧渲染或导出素材带入当前项目时，默认都作为普通资料导入：可阅读、分析、引用或作为生成输入，但不自动重建它们原来的方向、锚点、版本链和交付结构。

用户想让旧内容成为当前项目依据，应通过当前画布、聊天、关键结论、设计定义或方向操作明确建立关系。

## 6. 输出、完整项目归档与可恢复备份

### 6.0 Operation artifact 与恢复边界

Milestone 3 后，可恢复备份还需要保留 Operation / Proposal 的轻量结构化状态、citation snapshot 和 IndexedDB artifact 引用。备份不能只导出 workspace JSON，也不能把大型原始工具结果直接塞进 localStorage。

未来可恢复导出应同时收集：

```text
workspace JSON
IndexedDB 中仍被引用的二进制资产
Operation / Proposal 关联的 artifact 引用
```

原始网页正文、大型文档提取内容、页面预览和 provider 原始响应体不作为 workspace JSON 内容保存。需要保留时，应作为独立 artifact 存储并由结构化状态引用。

Morpho 保留三类不同的“带出项目”方式。它们不能混用。

### 6.1 导出最终成果

用于提交、展示、比赛、作品集或对外交付。

常见内容可包括：

```text
单张图片与素材包
展板 / PPT / 作品集的交付准备包
报名材料或文案
视频脚本或其他用户指定输出
```

其中，展板 / PPT / 作品集的交付准备包可包含：

```text
交付结构与模块顺序
逐页 / 逐模块文字、图注与说明
选定图片、来源与素材清单
明确缺口与补图建议
可选的页面 / 展板视觉参考图
```

Morpho 当前不承诺导出最终精细排版、可编辑 PPTX 或 Figma 级版式文件。用户可把准备包带到 Figma 等专业工具完成正式排版。导出最终成果关注“此刻要交什么”，不要求把全部过程数据塞进去。

### 6.2 导出完整项目归档

用于保存、复盘、交接和人类可读的项目过程。

完整归档应保留当前有效的过程材料与关系说明，例如：

```text
项目概览
当前设计定义
关键研究与结论
方向、主图与重要素材
决定与淘汰原因
阶段记录
交付计划与当前交付内容
来源、版本、关联、锚点和引用的必要说明
```

聊天记录不是默认必含内容。用户可选择：

```text
不导出聊天
只导出关键 AI 操作与决策摘要
导出完整阶段聊天
```

完整项目归档首先是便于阅读、复盘和交接的材料；它不等同于可继续编辑的恢复包。

### 6.3 导出可恢复备份

用于迁移设备、之后重新导入 Morpho 或继续编辑。

可恢复备份需要保留恢复项目所需的完整结构，例如：

```text
画布位置与层级
对象与资产关系
来源、版本、关联与局部借用关系
方向状态、设计定义、锚点
交付引用与模块结构
当前有效项目记忆与阶段记录
恢复项目所需的其他结构化数据
```

它不要求用户理解这些结构，也不把具体目录、JSON 字段、数据库或压缩格式锁死在产品文档里。

## 7. 恢复与重新导入

### 7.1 恢复可编辑项目

只有可恢复备份可以恢复为完整可编辑项目。

恢复行为：

```text
读取备份
→ 恢复为新的独立项目副本
→ 保留画布、对象、关系、状态、版本、锚点、交付引用与项目记录
→ 不覆盖当前已有项目
```

恢复后的默认名称可带轻量后缀，例如：

```text
夜间卫浴辅助产品 · 恢复副本
```

用户可随后自行改名。

### 7.2 重新导入完整项目归档

完整项目归档重新导入 Morpho 时，默认按“旧项目资料”处理：里面的图片、PDF、项目概览、阶段记录和导出素材可作为当前项目参考。

它不会自动把旧项目的主方向、锚点、版本链、交付结构和全部决定强行并入当前项目。这样用户只是想参考旧项目时，不会误把一整套旧状态塞进新项目。

### 7.3 普通文件与备份的区别

| 用户想做什么 | 使用什么 | 结果 |
|---|---|---|
| 把图片、PDF、PPT、草图带进当前项目 | 导入资料 | 作为普通资料进入当前画布 |
| 把旧项目导出的内容当参考 | 导入资料 / 项目归档 | 作为可阅读、可引用资料，不自动重建旧结构 |
| 继续编辑一个完整旧项目 | 恢复项目备份 | 恢复为新的独立可编辑项目副本 |

## 8. 本文件不锁定的事项

以下内容属于后续技术方案或产品深化，不在当前规则中定死：

- 资产实际存放在本地、云端、对象存储还是混合系统；
- 大文件上传、断点续传、同步、离线、版本冲突与加密；
- 文档阅读的格式覆盖范围、解析能力与 OCR 策略；
- 搜索索引、视觉相似检索、跨项目搜索和权限边界；
- 可恢复备份与归档包的精确文件目录、压缩格式和校验机制；
