# M5-D1 Document Reading And Text Location

## Scope

M5-D1 adds a lightweight workspace reader for already-parsed local file objects.

The reader shows the saved `documentExtract` text generated by the existing local parser. It is not a PDF, PPTX, Office, or original-document preview. It does not render PDF pages, reconstruct slide visuals, run OCR, edit documents, annotate documents, or extract fragments into new objects.

M5-D1 solves reading, local keyword search, text-block location, and user verification. M5-D2 is reserved for explicit selection of a passage, page, or slide-like unit, extraction into a separate traceable object, and later use in research, Compare, key conclusions, or design definitions.

## Eligibility

A file can open in the reader only when all of these are true:

- the object exists and `type === "file"`;
- `visibility === "active"`;
- `parseStatus === "parsed"`;
- `extractedAssetId` is present;
- `workspace.assets[extractedAssetId]` exists;
- that asset has `sourceType === "documentExtract"`;
- the IndexedDB Blob for the asset `storageKey` can be read.

Blocked states are explicit:

- unparsed files show that no readable local extract has been generated;
- parsing files show that reading is available only after parsing completes;
- failed files show the stored parse failure reason when present;
- missing `extractedAssetId`, missing asset metadata, wrong asset source type, missing Blob, or Blob read failure show local unavailability;
- hidden files are not a normal reader source and must be restored first.

The reader never falls back to title, summary, original file bytes, remote URLs, AI summaries, or mock data.

## Source Text

The source of truth is the IndexedDB Blob referenced by the `documentExtract` asset. Workspace JSON stores only asset metadata, parse status, `extractedAssetId`, extracted character count, optional parser count, parse time, and parse errors.

The reader does not copy extract text into `MorphoWorkspace`, `projectContinuity`, AI messages, operations, artifact proposals, DecisionRecords, localStorage schema data, or Compare analyses.

## Location Model

Current parser output is a plain saved extract string. It may include total character count and a parser-provided count such as PDF page count or PPTX slide count, but it does not persist a reliable source map with per-page, per-slide, paragraph, element, or coordinate boundaries.

The reader therefore locates text by local extract offsets:

- stable parsed text blocks;
- block index;
- block kind (`heading`, `paragraph`, or `preformatted`);
- `startOffset` and `endOffset` into the saved extract string;
- search match offsets inside a block and in the full extract;
- short inert text snippets around matches.

Without a real persisted source map, the UI must not claim "page 5", "slide 3", PDF coordinates, PPTX element positions, or page/slide jump navigation. If `extractedPageCount` exists, it is shown only as a parser count with a note that reliable page or slide mapping is not retained.

## Local Search

Search runs entirely in the browser against the already-loaded extract text.

Search input is treated as plain text, not a regular expression. The text is rendered by React as inert text; extracts are not executed as HTML, markdown, scripts, links, or code. Result lists and highlights are capped to avoid creating unbounded DOM for large extracts.

Search, previous/next navigation, result clicks, scrolling, and closing the reader do not call `/api/ai/chat`, `/api/ai/image`, external URLs, OCR services, or provider APIs.

## Workspace And AI Isolation

Opening, reading, searching, navigating, and closing the reader are transient UI actions. They do not:

- change task mode or work intent;
- change canvas selection or current focus;
- create AI messages;
- trigger semantic patches;
- trigger conversation checkpoints;
- create project-continuity events;
- create Compare analyses;
- create DecisionRecords;
- write operations or artifact proposals;
- mutate file parse status;
- rewrite assets or regenerate extracts.

Existing explicit AI paths are unchanged: when the user sends an AI task with selected parsed files, the bounded `documentExtract` context path remains controlled by `documentContext`. The reader itself does not authorize or preload AI context.

## UI Runtime

The reader opens from the bottom detail bar for a selected active parsed file. It is a temporary workspace floating panel, not a route, top-level stage, permanent navigation item, full-height inspector, browser window, or document-management page.

The panel shows:

- file title and original filename when available;
- MIME/type information when available;
- parse status;
- local extract character count;
- parser count only when actually stored;
- an explicit notice that the view is local parsed text rather than original layout;
- local search controls;
- block-level location and character ranges;
- a close button.

Asynchronous reads use request identity and an abort signal. If the user opens A, switches to B, or closes the reader while A is still loading, A's late result is ignored and cannot overwrite B or resurrect the closed panel.
