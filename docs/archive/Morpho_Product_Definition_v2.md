# 1. 产品概述与边界

## 1.1 产品名称

**Morpho**

Morpho 指向“形态变化、演化、从模糊到成形”。它适合表达产品设计概念阶段从零散想法、资料和图像尝试，逐步收束为完整视觉方案的过程。

## 1.2 一句话定义

**Morpho 是一款面向产品设计 / 工业设计概念阶段的 AI 画布工作台，帮助用户在一个连续项目空间中完成从模糊想法、调研和方向探索，到主视觉迭代、系列素材整理与最终展示输出的全过程。**

## 1.3 Morpho 要解决的问题

产品设计学生、初学者、早期 ID 设计师和独立设计师在概念阶段常常要在多个工具之间反复切换：

```text
聊天讨论
→ 收集资料与参考图
→ 写 Prompt
→ 去生图平台生成
→ 下载、整理、比较图片
→ 回到聊天继续讨论
→ 再做展板 / PPT / 作品集
```

问题不只是“缺一个更强的生图模型”，而是：

- 资料、分析、方向、图片和决策分散在不同地方；
- AI 很难持续理解整个项目；
- 用户经常忘记某个方向为什么被保留或淘汰；
- 主图改了之后，后续角度图、场景图和展示材料容易失去一致性；
- 最后要做展板、PPT、作品集时，已生成的图片和过程资料难以重新组织；
- 设计过程很难完整保存、交接、回溯或导出。

Morpho 的目标不是替代所有工具，而是成为概念设计过程的主工作台：

```text
把项目输入、调研、分析、设计定义、概念方向、图像迭代、比较、素材扩展、交付整理和项目归档连成一条连续链路。
```

## 1.4 产品边界

### Morpho 当前做什么

- 从一句模糊想法、课程 Brief、文件、图片或空白项目开始；
- 帮助用户探索项目方向；
- 收集、阅读、摆放和分析调研资料；
- 提炼发现、设计机会、现实约束和待验证问题；
- 形成设计定义；
- 生成多个概念方向，并尽早用图像预览方向；
- 围绕选定方向迭代主效果图；
- 锁定主视觉锚点；
- 基于锚点生成多角度图、细节图、场景图、CMF 图、设计示意等系列素材；
- 比较方向、图片和局部处理，记录保留与淘汰理由；
- 整理展板、PPT、作品集、素材包等输出内容；
- 导出最终成果、完整项目归档和可恢复备份；
- 通过项目记忆、阶段总结、对象关系和版本记录保持连续上下文。

### Morpho 当前不做什么

- 精确 CAD 建模；
- 工程级结构验证；
- 真实机械、电子、材料或制造验证；
- BOM、成本核算、供应链、量产工艺；
- 企业级 PLM / PDM；
- 取代 PowerPoint、Figma 或专业排版软件；
- 取代完整的 Office 文档编辑器；
- 重型多人协作和企业权限体系；
- 把概念图伪装成可直接制造的工程图纸。

> Morpho 所说的“全流程”，是 **ID 外观概念设计与视觉表达全流程**，不是从产品定义到量产的完整工业产品开发流程。

# 2. 目标用户、场景与核心问题

## 2.1 第一阶段目标用户

- 产品设计 / 工业设计学生；
- 设计初学者；
- 早期 ID 设计师；
- 独立设计师；
- 需要快速形成概念方案和展示材料的人。

共同特征：

- 经常从模糊课题或宽泛主题开始；
- 需要先找问题、调研、确定方向，再做形态和视觉；
- 会频繁使用 AI 聊天和 AI 生图；
- 不一定有很强的手绘、建模或渲染能力；
- 需要不断比较方案、修改图像、记录取舍；
- 最终通常要交课程展板、答辩 PPT、比赛材料或作品集页面。

## 2.2 核心场景

1. **课程项目 / Studio Project**  
   老师给一个宽泛主题，用户需要自己确定对象、调研、提出方案、生成视觉表达并做展示。

2. **比赛 / 创意项目**  
   用户有赛题或主题，但需要快速探索方案、做概念图和整理报名材料。

3. **作品集补充项目**  
   用户从零构建一个完整设计项目，既需要过程，也需要最终视觉和叙事材料。

4. **已有方案的图像深化**  
   用户已经有草图、模型、初步渲染或文字方案，需要继续迭代主图并补齐展示素材。

5. **个人概念设计**  
   用户有一个大概想法，想将其逐步发展成可展示的产品概念。

# 3. 核心原则

## 3.1 可以从空白开始

用户不必在创建项目时填写完整 Brief。可以从：

- 一句话；
- 一个课程文件；
- 一张图；
- 一份旧方案；
- 一段聊天记录；
- “我不知道做什么”；

开始。

## 3.2 先看见方向，再决定方向

概念方向不能只靠文字选择。每个有价值的方向应尽早生成快速视觉预览，让用户基于“策略 + 图像”判断是否继续。

## 3.3 主效果图优先

主图没有稳定之前，不应过早批量生成多角度图、细节图、场景图、CMF 图等下游素材。

```text
先确定产品到底长什么样
→ 再基于它生成其他表达图
```

## 3.4 主视觉锚点是后续图像的一致性基础

主视觉锁定后，后续素材默认继承：

- 产品架构；
- 核心比例；
- 关键功能结构；
- 材质与 CMF 基线；
- 视觉语言；
- 当前主方向的设计策略。

## 3.5 画布以项目推进为主，不是节点工作流

Morpho 的画布是设计过程地图，不是复杂节点图，也不是单纯图片墙。它默认不显示大量关系线，而是靠阶段区域、方向轨道、空间位置和对象归属表达项目结构。

## 3.6 人做关键决定，AI 做分析、建议与执行

AI 可以分析、归纳、生成、推荐和执行；但以下内容必须由用户明确确认，或至少经过明确确认动作：

- 设计定义成为当前有效版本；
- 某条方向成为主方向、备选或淘汰；
- 某张图成为主视觉锚点；
- 关键结论写入项目长期记忆；
- 高成本或影响范围大的操作执行；
- 最终交付结构确定。

## 3.7 信息默认简洁，详情统一去底部详情栏

画布对象只显示快速判断所需的信息。选中对象后，详细信息统一进入底部详情栏，不在不同对象旁边弹出不同形式的详情窗口。

## 3.8 过程可以回看、迁移和导出

项目不只保存最后几张图片，也要保留资料、方向、比较、取舍、版本、图像来源和输出结构。

# 4. 总体工作流

## 4.1 主流程

```text
开始与输入
→ 调研
→ 设计定义
→ 概念方向分叉
→ 各方向快速预览
→ 比较与选择
→ 主图迭代
→ 主视觉锚点
→ 扩展素材
→ 交付整理
→ 导出与项目归档
```

## 4.2 Explore 的位置

“探索”不是所有项目都必须经过的独立大阶段。

- 用户没有方向：从开始区进入探索，先生成可做的项目方向；
- 用户已有方向：直接进入调研；
- 用户已有成熟方案：可以直接从主图迭代、扩展素材或交付整理开始。

因此，Explore 是一条可选的前置分流，而不是强制步骤。

## 4.3 发散与收束逻辑

```text
共同输入与调研
→ 共同设计定义
→ 多条概念方向并行探索
→ 比较与选择
→ 一条主方向深入迭代
→ 基于主视觉扩展素材
→ 多种交付物分支整理
```

# 5. 画布空间结构与工作台布局

## 5.1 总体空间：左到右推进，上下方向分叉

画布应像一张横向展开的项目地图，而不是从上到下堆叠的流程长页。

```text
左                                                                                      右
开始 → 调研 → 设计定义 → 方向分叉 → 比较 → 主图迭代 → 主视觉锚点 → 扩展素材 → 交付
                             ├ 方向 A：预览 → 停止 / 淘汰
                             ├ 方向 B：预览 → 主方向 → 继续向右
                             └ 方向 C：预览 → 备选
```

空间规则：

- **左到右**：项目推进、设计逐渐收束；
- **上下方向**：不同概念方向或局部子分支；
- **分叉前**：共同输入、调研和设计定义；
- **分叉后**：每条方向沿自己的横向轨道发展；
- **主方向选出后**：项目重新收束为一条右侧主线；
- **交付阶段**：再按展板、PPT、作品集等输出形式向上下分区。

## 5.2 阶段区域

每个阶段是画布中的轻量区域，类似 Figma Section：

- 很浅的背景差异；
- 左上角阶段名称；
- 必要时的轻边界；
- 可调整范围；
- 可折叠为摘要；
- 左侧导航点击后自动定位与缩放。

阶段区域不应是重型页面框，也不应阻止用户跨区域摆放、拖动和比较内容。

## 5.3 工作台布局

```text
┌─────────────────────────────────────────────────────────────────────┐
│ [Morpho] 项目名称 ▾                                活动任务指示（如有） │
├───────┬──────────────────────────────────────────────────────┬──────┤
│ 左侧  │                      无限画布                         │ 右侧 │
│ 阶段  │   开始 → 调研 → 定义 → 方向 → 迭代 → 交付            │ AI   │
│ 导航  │                      底部详情栏按需展开                │ 聊天 │
└───────┴──────────────────────────────────────────────────────┴──────┘
```

### 顶部

默认保持极简：

```text
[Morpho] 项目名称 ▾
```

项目下拉菜单包含：

```text
项目概览
项目 Brief
项目记忆
阶段记录
导入资料
导出与归档
项目设置
```

保存状态只做轻量提示。模型选择不放在全局顶部，而是属于具体生成任务或 AI 执行设置。

### 左侧：阶段导航

默认收起，显示简洁阶段标签或图标：

```text
开始
探索
调研
设计定义
预览
比较
迭代
扩展
交付
```

点击后：

- 画布定位到对应区域；
- 自动缩放到合适范围；
- 右侧 AI 切换到对应阶段上下文。

展开后可补充：

- 当前阶段状态；
- 资产入口；
- 项目记忆与阶段记录入口；
- 输出与导出入口。

### 画布内工具栏

放在画布左侧，保持轻量，不做完整 Figma / CAD 工具箱：

```text
选择 / 移动
添加
导入
标注
AI 操作
缩放 / 项目地图
```

含义：

- **选择 / 移动**：单选、多选、框选、移动、组合；
- **添加**：文字、简单注释、箭头、区域等；
- **导入**：文件、网页链接、旧项目资料等；
- **标注**：圈选、箭头、笔迹、局部修改说明；
- **AI 操作**：对当前选中对象执行直接操作；
- **缩放 / 项目地图**：查看项目全局结构与快速定位。

直接拖入文件、图片或粘贴截图应是同样重要的入口，不要求用户每次先点“导入”。

### 右侧：常驻 AI 聊天

右侧始终是 AI 聊天，不会因为用户选中对象而变成 Inspector。

选中对象后，聊天顶部出现可移除的上下文标签，例如：

```text
当前讨论对象
[主效果图候选 03 ×] [方向 B ×]
```

右侧聊天包括：

- 当前阶段；
- 当前上下文对象；
- 少量建议操作；
- 连续聊天记录；
- 输入框；
- 输入框旁的 AI 执行方式切换。

输入框旁提供：

```text
自动执行 ▾
先确认
```

用户可随时切换。它不是项目级设置，也不区分“全局 / 本次”；当前选中的模式决定接下来 AI 的可执行操作如何处理。

### 底部详情栏

底部详情栏默认隐藏。用户选中对象后，先出现紧凑标题条；点击标签或展开后才显示详细内容。

用户界面不需要给它起一个额外名称。显示对象本身的标题即可，例如：

```text
主效果图候选 03
[信息] [来源] [版本] [关联] [决策]
```

或：

```text
方向 B：模块化墙面支撑系统
[概览] [依据] [视觉] [记录]
```

规则：

- 不选对象：隐藏；
- 选对象：出现紧凑标题条；
- 用户手动展开后：显示详情；
- 用户手动收起后：后续选对象只更新标题，不强行再次完全展开；
- 多选对象：切换成比较相关的操作。

### 生成状态

不保留一个固定占据底部的任务队列。

- 生成中的占位状态出现在发起任务的图像、方向或区域旁；
- 结果落在对应任务位置；
- 有活动任务时，顶部或画布边缘可显示一个很轻的任务指示，如 `⟳ 2`；
- 点击任务指示后才打开临时任务列表。

# 6. 每个阶段的用户流程与画布内容

## 6.1 开始与输入

### 用户做什么

- 输入一句话、课程 Brief、赛题、已有方案；
- 拖入图片、PDF、PPT、Word、草图、截图、网页链接或旧聊天记录；
- 也可以直接说“我不知道做什么”。

### 画布上出现什么

- 图片：完整图片对象，可移动、缩放、裁切、叠放；
- 文档：文件预览对象；
- 文本：普通文本或项目说明；
- 初步整理出的项目输入区域。

### 文档阅读

PDF、PPT、Word 等文档不应只是死文件。

- PDF：双击后可在当前画布中展开阅读、翻页、缩放；
- PPT / Word：第一阶段以预览、阅读、提取页面、图片和文本为主，不做 Office 级编辑；
- 用户可将某页文档放到画布中作为独立页面 / 图片对象；
- 用户可提取一段文字作为资料引用。

### Explore 分流

如果用户没有方向，AI 帮助生成可继续做的项目方向，并说明其用户、场景、可视化潜力和下一步调研重点。用户已有方向时可直接跳过。

---

## 6.2 调研

### 用户做什么

- 把竞品、用户场景、参考图、CMF、文档、网页和文字摆到调研区；
- 框选一批资料后，让 AI 分析；
- 也可以指定问题，例如：

```text
分析这些竞品的共性和缺口。
这些场景里用户真正不方便的地方是什么？
整理这些参考图的形态和视觉倾向。
```

### 画布上出现什么

除原始资料外，AI 会生成一张 **研究与分析** 卡片。

它是一张可阅读的文字卡片，包含 AI 基于当前资料得出的多条候选内容：

```text
研究与分析

发现
① ……
② ……

设计机会
③ ……
④ ……

现实约束
⑤ ……

待验证
⑥ ……
```

其中每一条都是独立可选的内容，而不是一整段不能操作的报告。

### 用户如何处理研究与分析中的条目

用户可直接点击某一条。底部详情栏显示：

- 该条的完整表述；
- 来源资料；
- AI 的理由或证据摘要；
- 编辑；
- 保留为关键结论；
- 加入设计定义；
- 不采用；
- 与 AI 讨论。

### AI 推荐筛选

用户不需要逐条手动选择。

研究与分析卡片提供：

```text
[AI 推荐保留]
```

AI 会说明：

- 建议优先保留哪些条目；
- 每条推荐理由；
- 哪些暂不保留；
- 哪些更适合保持为待验证问题。

用户可以：

```text
[按建议保留]
[自己调整]
```

AI 推荐不会自动把结论写成项目既定事实。

## 6.3 关键结论

### 它是什么

用户明确保留，或确认 AI 推荐后保留的调研内容，会变成调研区中的独立关键结论卡。

每张卡只表达一个明确意思。

### 四类结论

| 类型 | 含义 |
|---|---|
| 发现 | 调研里已经观察到的事实、规律或问题 |
| 设计机会 | 基于发现，值得在方案中尝试的方向 |
| 现实约束 | 方案必须考虑、不能忽略的条件 |
| 待验证 | 当前证据不够，后续仍需确认的问题 |

### 画布上的样子

```text
┌──────────────────────────┐
│ 设计机会                 │
│                          │
│ 将支撑从单点扶手延伸为   │
│ 连续动作中的支持系统。   │
└──────────────────────────┘
```

相近的文字卡不只依靠颜色区分：

- 左上角有明确类别文字；
- 配合轻量图标或结构差异；
- 使用很浅的辅助色；
- 不用大色块，也不做四种夸张的卡片样式。

详细来源、关联方向、状态和历史都在底部详情栏中查看。

---

## 6.4 设计定义

### 用户做什么

用户选中若干关键结论后，可以点击：

```text
[整理为设计定义]
```

AI 生成草稿，用户可编辑、增删和确认。

### 设计定义解决什么

设计定义不是调研报告，也不是具体方案。它回答：

```text
这个项目到底要解决什么？
面向谁、在哪个场景？
后面做方案时应该遵循什么？
哪些事情不应该做？
```

### 画布上的样子

设计定义是设计定义区中央的一张较大、文档式对象，包含：

1. 核心问题；
2. 目标用户与核心场景；
3. 设计目标；
4. 设计原则；
5. 边界与避免项；
6. 当前视觉基调与待确认问题。

它不应过早锁定：

- 最终具体形态；
- 精确尺寸；
- 最终结构；
- 最终配色；
- 最终 Prompt；
- 最终图片构图。

确认后的设计定义是项目共同前提。后续方向都以它为基础。

---

## 6.5 概念方向

### 用户做什么

用户可以：

- 让 AI 基于设计定义生成 3–5 个方向；
- 自己新建一个方向；
- 从已有方向分出一个局部变体。

### 什么算真正不同的方向

不同方向应该在以下一个或多个层面有真实差异：

- 产品架构；
- 核心支持或使用机制；
- 产品放置位置；
- 用户使用路径；
- 单体产品还是系统关系；
- 形态语言；
- 视觉表达策略。

不能只是换颜色、换材质或把“科技感”改成“极简感”。

### 画布上的样子

方向位于设计定义右侧的分叉区，并作为每条横向方案轨道的起点。

方向卡只显示：

- 方向名称；
- 一句话策略；
- 3 个关键词；
- 当前状态。

例如：

```text
方向 B
模块化墙面支撑系统

用低施工的可组合模块，
为进入、转身和起身提供连续支撑。

低施工 · 连续支撑 · 家居化

待预览
```

方向的研究依据、视觉参考、预览数量、决策记录等，在选中后通过底部详情栏查看，不塞在卡面上。

### 方向状态

```text
待预览
探索中
主方向
备选
已淘汰
```

- 待预览：已提出但尚未视觉化；
- 探索中：已生成预览，尚在判断；
- 主方向：比较后被选中，继续深化；
- 备选：保留，但暂不继续推进；
- 已淘汰：停止推进，但保留原因和可借用局部。

---

## 6.6 方向预览

### 目标

Preview 只用于快速判断：

```text
这条方向大概会长成什么样？
视觉气质和形态潜力是否值得继续？
```

它不是精修主图阶段。

### 用户操作

选中方向后点击：

```text
[生成预览]
```

用户只需要选择生成数量：

```text
2 张 / 4 张 / 6 张
```

不要求用户先选复杂的构图、风格、材质或提示词设置。

AI 自动根据：

- 已确认设计定义；
- 当前方向策略；
- 当前方向关联的机会、约束和参考；
- 当前项目的视觉倾向；
- 预览阶段内部的生成模板与方法；

组织生成内容并出图。

高级控制可以在未来提供，但默认收起，不干扰主流程。

### 画布上的样子

预览图直接出现在对应方向卡右侧。

```text
方向 B
   → [预览图 1] [预览图 2]
     [预览图 3] [预览图 4]
```

图像就是完整图片对象。角落只显示轻标签，例如“预览”。

### 可对预览图执行的动作

在底部详情栏或选中后的轻量操作中：

```text
带入比较
继续发展
保留局部
不采用
与 AI 讨论
```

“保留局部”指用户可以保留某张图中的局部形态、连接方式、材质处理或构图思路，供主方向或其他方向后续借用。

---

## 6.7 比较与选择

### 目标

比较不是把所有图塞到一个大表格里，而是帮助用户从多个方向中选出：

```text
主方向
备选
已淘汰
可借用局部
```

### 画布上的样子

比较区是一个摆放候选图的区域，不是一张“比较卡”。

用户从每条方向中选择 1–2 张代表图带入比较区：

```text
方向 A                 方向 B                 方向 C
[代表图]               [代表图]               [代表图]
[代表图]               [代表图]               [代表图]
```

AI 可以分析各方向的差异、优势、风险和与设计定义的匹配度，但不替用户自动做最终决定。

用户可以记录类似：

```text
采用方向 B 的模块化结构，
保留方向 C 的夜间路径引导逻辑。
```

这类“保留局部”会进入主方向后续上下文。

---

## 6.8 主图迭代

### 目标

主图迭代只服务于已经选中的主方向。

它要解决的是：

```text
这个产品最终到底长什么样？
它的形态、比例、核心结构、材质和视觉语言是否可信？
```

### 用户操作

用户选中主方向中的某张图，在右侧聊天中直接描述修改需求，例如：

```text
保留现在的模块结构和整体比例，
但让扶手与主体更一体化，减少外露工程零件感。
```

### AI 执行方式

输入框旁可随时切换：

```text
自动执行
先确认
```

- **自动执行**：AI 理解后直接执行生成或编辑；
- **先确认**：AI 先给出简短执行卡，说明保留什么、修改什么、生成几张，用户点击确认后才执行。

确认卡不默认展示完整 Prompt；默认用用户能理解的摘要。技术详情可折叠查看。

即使处于“自动执行”，以下操作仍应强制确认：

- 锁定或替换主视觉锚点；
- 批量删除或大范围覆盖；
- 写入关键项目记忆；
- 高成本或大批量生成；
- 未来的联网委托调研等高影响动作。

### 画布上的样子

被选中的图片形成向右推进的主线；每轮生成的其他变体留在当前轮次附近。

```text
起始主图
   → 第 1 轮变体
      → 选中图
         → 第 2 轮变体
            → 选中图
               → 第 3 轮……
```

每轮都有一条简短修改意图，帮助用户回看：

```text
第 2 轮
保留模块化结构与比例；
减少外露连接件；
强化家居卫浴感。
```

完整 Prompt、模型、参考图、参数等放在图片的版本 / 信息详情中，不平铺在画布上。

---

## 6.9 主视觉锚点

### 用户操作

当某张主图足够代表最终方案时，用户点击：

```text
[锁定为主视觉]
```

系统提供简短确认，让用户确认当前要保留的核心特征，例如：

- 关键结构；
- 轮廓和比例；
- 扶手或主要功能部件关系；
- CMF 基线；
- 视觉风格。

### 画布上的样子

它仍是一张图片，只在角落有明确轻标签：

```text
主视觉锚点
```

### 替换锚点

锚点不是永久冻结。若用户替换锚点，系统应列出可能受影响的下游素材，并提供：

```text
仅替换锚点，保留现有素材
替换锚点，并标记相关素材待复核
```

系统默认只标记“待复核”，不自动删除或重生成下游内容。

---

## 6.10 扩展素材

### 目标

主视觉锚点之后，用户开始补齐“讲清楚这个方案还需要哪些图”。

这不是固定的一整套图，也不是自动生成所有可能素材。

### 用户操作

用户可以直接选：

```text
多角度图
细节图
使用场景
CMF / 配色
结构示意
展示主视觉
自定义
```

也可以点击：

```text
[生成素材建议]
```

AI 根据项目、主视觉、已有素材和预期交付物，给出“建议补什么、为什么补”的清单。用户保留需要的项目后再生成。

### 画布上的样子

主视觉锚点右侧形成多个小型素材区域：

```text
主视觉锚点
     → 多角度图
     → 细节图
     → 使用场景
     → CMF / 配色
     → 结构示意
```

每个区域里直接放实际图片，不再套一层“素材卡”。

### 素材的表达边界

应明确区分：

- **概念表达**：主视、场景、CMF、展示视觉；
- **设计示意**：角度、连接关系、安装逻辑、爆炸示意、尺寸说明。

后者不能被暗示为工程上精确可制造的图纸。

---

## 6.11 交付整理

### 目标

交付阶段不是一键生成一份最终 PPT 或直接替代 Figma 排版。

它首先要解决：

```text
我现在要交什么？
已经有什么？
缺什么？
每张图和每段文字应该用来讲什么？
```

### 用户操作

用户选择一个或多个交付物：

```text
展板
PPT
作品集页面
图像素材包
报名材料 / 文案
视频脚本
其他
```

### 画布上的样子

交付不是一张“大交付物卡”。最右侧是交付区域，里面再按实际输出形式划分子区域。

例如：

```text
Deliver
├─ 展板区域
├─ PPT 区域
├─ 作品集区域
└─ 素材包区域
```

#### 展板区域

展板区域中直接摆放：

- 展板内容结构；
- 已选图片；
- 文字要点；
- 图注；
- 待补充图片占位；
- AI 建议；
- 用户批注。

例如：

```text
关键结构与细节

[扶手连接细节图]
[安装示意：待补充]
低施工卡扣式安装说明
```

#### PPT 区域

PPT 区域可以按页组织：

```text
01 项目背景
02 调研与发现
03 设计定义
04 方向比较
05 最终方案
06 结构与细节
07 使用场景
08 总结
```

每页下放标题、图片、文字要点和缺失占位。第一阶段不必做成完整 PPT 编辑器。

### 交付阶段发现缺图时

系统创建明确的补图任务，继续在交付区右侧或扩展素材末端生成，不要求用户跳回很远的画布左侧。

```text
交付整理
→ 发现缺少安装示意
→ 创建补充素材任务
→ 生成并回填展板 / PPT 区域
```

# 7. 画布中的主要对象

## 7.1 图片

### 画布表现

图片就是完整图片对象：

- 可移动；
- 可缩放；
- 可裁切；
- 可叠放；
- 可框选；
- 可直接作为参考、AI 输入或交付素材。

不要把正常画布中的图片强制塞进缩略图卡片。

### 图片角色标签

图片角落可有非常轻的角色标签：

```text
预览
主图候选
主视觉锚点
细节
场景
CMF
设计示意
```

图片的来源、版本、Prompt、模型、关联方向等详细信息统一在底部详情栏查看。

## 7.2 文档

PDF、PPT、Word、网页等以文件预览对象出现。

用户可：

- 双击展开阅读；
- 提取页面；
- 提取图片；
- 提取文字；
- 作为调研资料与 AI 讨论；
- 关联到研究与分析或方向。

## 7.3 研究与分析

研究与分析是一张由 AI 根据一批资料生成的文字卡片。它里面列出多条可单独选中的候选内容：发现、设计机会、现实约束、待验证。

它不是最终结论集合，而是用户筛选和 AI 推荐筛选的中间结果。

## 7.4 关键结论

关键结论是用户确认保留的单条研究内容。每张卡只写一个结论。

详细信息统一去底部详情栏。

## 7.5 设计定义

设计定义是项目共同前提的文档式对象，位于设计定义区中央。

它连接调研与概念方向，不属于任何单独方向。

## 7.6 概念方向

方向卡是每条方案轨道的起点。它显示策略和状态，而不是完整研究报告。

## 7.7 方案图

“方案图”是对所有视觉资产的统一称呼，包括预览图、主图、主视觉锚点、多角度图、细节图、场景图、CMF 图和设计示意等。

在用户界面中，它们都以图片形式存在，只通过轻标签标识角色。

## 7.8 阶段区域与交付区域

它们是空间容器，不是普通内容卡片：

- 阶段区域帮助用户理解项目当前走到哪里；
- 交付区域帮助用户直接组织展板、PPT、作品集等可见内容。

# 8. AI 的角色、执行方式与上下文规则

## 8.1 AI 在不同阶段的职责

| 阶段 | AI 的主要职责 |
|---|---|
| 开始 | 理解输入、判断用户当前状态、建议下一步 |
| 探索 | 从宽泛主题中提出可做方向，帮助选择项目切入点 |
| 调研 | 分析资料、生成研究与分析、推荐保留内容 |
| 设计定义 | 将关键结论收束成设计定义草稿，指出缺口和矛盾 |
| 方向 | 生成真实不同的概念方向，说明差异和风险 |
| 预览 | 根据方向与项目上下文自动组织生成内容并快速出图 |
| 比较 | 对比候选方向和图片，帮助解释差异与取舍 |
| 迭代 | 根据用户对主图的反馈生成变体、局部修改或视觉调整 |
| 扩展 | 依据主视觉锚点规划并生成系列素材 |
| 交付 | 组织展板、PPT、作品集结构，盘点已有素材和缺失内容 |

## 8.2 AI 能做什么，不能擅自做什么

### 可以主动做

- 根据选中对象进行总结、分析、提炼；
- 生成研究与分析；
- 推荐关键结论；
- 提出方向草案；
- 组织生成任务；
- 建议比较维度；
- 生成素材建议；
- 标记生成完成、草案、待验证、建议待复核；
- 解释它即将执行的操作。

### 不应擅自做

- 直接把 AI 结论写成用户确认的项目事实；
- 自动指定主方向、备选或淘汰方向；
- 自动锁定主视觉；
- 自动删除历史素材；
- 自动大批量生成内容；
- 自动将敏感或未经确认的信息写入项目记忆；
- 默认读取整张画布和全部历史聊天。

## 8.3 上下文范围

每次 AI 调用应优先使用：

```text
当前阶段规则
+ 当前有效项目记忆
+ 与当前任务直接有关的阶段总结
+ 当前选中的对象或用户指定对象
+ 当前方向 / 主视觉锚点（如适用）
+ 用户最新输入
```

AI 不应默认把整个项目、所有旧图、所有被淘汰方向和所有聊天记录塞进上下文。

## 8.4 阶段聊天与长期项目理解

Morpho 采用“阶段聊天 + 项目记忆”而不是一条无限增长的总聊天。

- 右侧聊天是连续可见的，但内部按阶段维护重点上下文；
- 系统可自动压缩长聊天，不要求用户手动操作；
- 用户切换阶段、做关键决策或聊天过长时，系统可更新阶段总结；
- 历史阶段并不是永久处于“活跃聊天”，重新回到旧阶段时，AI 基于当前有效信息、历史摘要和用户新输入继续工作。

# 9. 状态、版本、决策与项目记忆

## 9.1 状态的原则

状态有必要，但不能做得像任务管理工具。

```text
状态存在
≠
到处堆标签和颜色
```

状态只放在真正需要的对象上，并以右上角轻标记、轨道弱化、折叠或待复核提示等方式表现，不让整张卡片被状态颜色主导。

## 9.2 建议状态

| 对象 | 状态 |
|---|---|
| 关键结论 | 草案、已确认、待验证、已替代 |
| 概念方向 | 待预览、探索中、主方向、备选、已淘汰 |
| 方案图 | 生成中、候选、已选、主视觉锚点、待复核 |
| 交付模块 | 已有、待补充、已完成 |

### 谁能改变状态

AI 可自动标记：

- 草案；
- 待验证；
- 生成中；
- 生成完成；
- 建议待复核。

用户确认后才能标记：

- 已确认；
- 主方向；
- 备选；
- 已淘汰；
- 主视觉锚点；
- 交付模块已完成。

## 9.3 版本与回退

### 图像版本

主图迭代中的每一轮都记录：

- 从哪张图继续；
- 本轮修改意图；
- 生成结果；
- 用户最后选中的图。

未被选中的图保留在当前轮次附近，可回看、重新发展或保留局部。

### 设计定义与方向修改

- 修改设计定义草稿：不立即影响长期项目记忆；
- 确认新的设计定义：更新当前有效版本；
- 已存在方向或素材如果可能受影响：标记“建议复核”，不自动废弃；
- 修改主方向核心策略：创建修订记录，并提示相关下游内容检查一致性。

## 9.4 项目记忆

项目记忆分两类：

### 当前项目记忆

记录当前仍有效、跨阶段需要持续使用的信息，例如：

```text
project_overview.md
设计概述、项目目标、当前阶段

design_brief.md
当前有效设计定义

user_preferences.md
用户确认过的偏好与明确避免项

decision_log.md
关键选择、理由、时间

rejected_directions.md
已淘汰方向与原因

open_questions.md
尚未确认的问题

output_plan.md
当前交付物与输出计划
```

### 阶段总结

记录一个阶段结束时发生过什么，是历史快照。应包括：

- 阶段目标与状态；
- 本阶段成果；
- 关键决策与理由；
- 淘汰内容与理由；
- 用户偏好与反感点；
- 稳定约束；
- 未解决问题；
- 下一步建议。

## 9.5 写入规则

| 事件 | 是否写入当前项目记忆 |
|---|---|
| 用户随口提出一个想法 | 否，默认只在当前聊天中 |
| AI 生成方向候选 | 否，仍是候选 |
| 用户保留关键结论 | 是 |
| 用户确认设计定义 | 是 |
| 用户设定主方向 / 备选 / 淘汰 | 是 |
| 用户确认主视觉锚点 | 是 |
| 普通图像生成或普通变体 | 否，除非用户选中或产生关键决策 |
| 用户确认交付结构 | 是 |
| 方向被淘汰且有理由 | 是 |

## 9.6 回到旧阶段时的规则

回到过去阶段不等于恢复原来的完整聊天状态。

系统应使用：

- 当前项目记忆；
- 原阶段总结；
- 与当前修改相关的对象；
- 用户最新输入；

继续工作。

原阶段总结保留为历史；新的修改形成修订记录。若修改会影响下游方向、主图或交付内容，系统只提示“建议复核”，不自动替用户推翻后续成果。

# 10. 交付、导出与项目归档

## 10.1 三类导出

### 导出最终成果

适合交作业、比赛、汇报、作品集整理。主要导出：

- 当前主方案；
- 已选最终图片；
- 展板 / PPT / 作品集中的内容；
- 输出文案、图注和素材包。

### 导出完整项目归档

适合保留整个设计过程、交接、复盘和未来复用。默认包含：

- 原始资料；
- 研究与分析；
- 已保留关键结论；
- 设计定义；
- 所有方向，包括主方向、备选和淘汰方向；
- 预览图、迭代图、主视觉锚点和扩展素材；
- 决策记录；
- 输出计划与交付内容；
- 当前有效项目记忆；
- 画布总览。

### 导出可恢复备份

在完整项目归档基础上，额外包含项目结构、画布位置、对象关系、版本、状态和其他系统数据，用于之后重新导入 Morpho 或迁移设备。

## 10.2 聊天记录与项目记忆的导出

### 聊天记录

完整聊天记录默认不导出，因为其中可能有大量试探、重复、无关内容或隐私信息。

导出选项建议为：

```text
不导出聊天记录
导出关键 AI 操作与决策摘要
导出完整阶段聊天记录
```

默认选择：**导出关键 AI 操作与决策摘要**。

### 项目记忆

当前有效项目记忆应默认包含在完整项目归档中。

阶段总结可以作为可选项：

```text
导出当前有效项目记忆
导出历史阶段总结
```

## 10.3 项目归档包的结构

项目归档应同时有：

1. **人类可读内容**：Markdown、图片、PDF、素材目录；
2. **系统可恢复内容**：JSON 等结构化数据。

示例：

## 10.4 项目关系与画布连线

系统需要记录必要关系，例如：

```text
资料 → 支撑 → 关键结论
关键结论 → 被纳入 → 设计定义
设计定义 → 引导 → 概念方向
概念方向 → 产生 → 方案图
方案图 → 派生 → 方案图
方案图 / 方向 → 被用于 → 交付区域
```

这不代表画布默认画满连线。

平时依靠阶段位置、方向轨道和区域归属阅读项目。只有用户主动查看来源、依据、版本或交付引用时，才临时显示相关关系或虚线，并可跳转回源对象。

# 11. 当前第一阶段范围与未来能力

## 11.1 第一阶段必须走通的核心链路

第一阶段优先目标不是覆盖所有可能功能，而是让用户真正完成：

```text
输入资料
→ 调研与分析
→ 保留关键结论
→ 设计定义
→ 概念方向
→ 快速预览
→ 比较
→ 主图迭代
→ 锁定锚点
→ 扩展素材
→ 交付整理
→ 导出项目
```

优先能力：

- 项目创建与画布；
- 图片 / 文件导入与文档阅读；
- 阶段区域和横向画布导航；
- 研究与分析、关键结论、设计定义、方向、图片等主要对象；
- 右侧阶段 AI 聊天；
- 输入框旁“自动执行 / 先确认”；
- 预览生成；
- 主图迭代与锚点；
- 基础扩展素材；
- 交付区域的内容组织；
- 项目归档导出基础版；
- 基础项目记忆和阶段总结。

## 11.2 后续能力，不进入当前第一阶段

### 委托调研

未来可以支持用户确认研究范围后，由系统调用合规网页、商品和社媒数据源生成带来源、可信度和可编辑结论的研究资料包。

它涉及：

- 研究计划；
- 网页 / 商品 / 评论 / 社媒等数据源；
- 来源与版权；
- 数据去重；
- 评论与情绪分析；
- 图文对应；
- 成本、失败处理、合规与隐私；
- 用户确认后再进入项目记忆。

这是一套独立子系统，不应在第一阶段以一个简单按钮草率实现。

### 其他后续能力

- 多人协作、评论与权限；
- 更复杂的项目资产库与搜索；
- 更成熟的 PPT / 展板自动生成与可编辑排版；
- 高级模型路由与用户自带模型；
- 节点式工作流；
- CAD / 3D / 工程数据接入；
- 更完整的本地同步、云端迁移和版本管理。

# 14. 附录：下个窗口交接提示词

```text
我正在继续设计一个名为 Morpho 的产品。请以我上传的《Morpho 产品定义文档 v2》为唯一主文档，v1 已废弃，不要再以 v1 的结构或结论为准。

Morpho 是一款面向产品设计 / 工业设计概念阶段的 AI 画布工作台。它服务的是从模糊想法、调研和概念方向，到主视觉迭代、系列素材整理、展板 / PPT / 作品集输出的 ID 外观概念设计与视觉表达流程；它不是 CAD、工程结构、制造或量产工具。

已经确定的关键规则：
1. 画布总体按左到右推进；共同输入、调研和设计定义在左侧，概念方向在中部向上下分叉，每条方向沿自己的横向轨道向右发展；主方向选出后重新收束为一条主线，交付物在最右侧按展板、PPT、作品集等区域分开整理。
2. 右侧永远是阶段 AI 聊天，不会因选中对象变成属性面板；选中对象会作为可移除上下文标签进入聊天。
3. 详细信息统一在底部详情栏查看；画布对象本身只显示必要信息。
4. 图片在画布上就是完整可缩放图片，不是缩略图卡片；PDF / PPT / Word 可作为资料预览，支持在画布中展开阅读、提取页面 / 图片 / 文字，但第一阶段不做 Office 级编辑。
5. 调研中，用户选一批资料让 AI 生成“研究与分析”卡；卡中包含可单独选择的发现、设计机会、现实约束、待验证内容。用户可自己保留，也可以点“AI 推荐保留”，再按建议保留或自己调整。被保留的内容变成独立“关键结论”卡。
6. 关键结论 → 设计定义 → 概念方向。设计定义是项目共同前提，不是具体方案。
7. 每个概念方向先生成 2 / 4 / 6 张快速预览。用户不必先配置复杂选项，AI 根据设计定义、方向、参考和内部生成方法自动组织生成内容。
8. Compare 用于从多条方向中选择主方向、备选和淘汰，并允许保留其他方向的局部逻辑。
9. 主图迭代只服务主方向。输入框旁可随时切“自动执行 / 先确认”；重要或高影响动作仍强制确认。
10. 主视觉锚点确定后才扩展多角度、细节、场景、CMF、设计示意等素材。替换锚点时，系统只提示下游素材待复核，不自动删除或重生成。
11. Deliver 不做成一张大卡，而是交付区域：展板区域、PPT 区域、作品集区域等，里面直接摆放图片、文字、图注和待补充占位。
12. Morpho 支持最终成果导出、完整项目归档和可恢复备份；完整聊天记录是可选导出，当前项目记忆默认进入完整归档。
13. 当前项目记忆记录有效结论、设计定义、主方向、锚点、决策和输出计划；阶段总结是历史快照。AI 候选、普通图像生成、随口想法默认不直接写进长期记忆。

下一步优先继续讨论“画布具体操作规则”：拖放、关联、多选、分组、折叠、淘汰方向的处理、关系线何时显示、图片和交付区域之间如何引用。讨论时请用直接、常见、容易理解的中文，不要自造生硬术语，不要重复已经确认且我没有提出疑问的内容。
```
