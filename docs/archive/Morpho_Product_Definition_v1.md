# Morpho 产品定义文档 v1

> 面向 ID 外观概念设计全流程的 AI 画布工作台  
> 当前版本：v1  
> 当前阶段：产品定位、用户流程、信息架构、AI 上下文机制收束  
> 适用范围：后续产品方案、原型设计、功能拆解、开发规划的交接基础

---

## 0. 当前结论摘要

Morpho 是一款面向产品设计 / 工业设计学生、设计初学者、早期 ID 设计师和独立设计师的 AI 画布工作台。它服务的“全流程”不是工程落地、结构设计、CAD、制造和量产意义上的工业设计全流程，而是 ID 外观概念设计语境下，从没有想法到形成可展示视觉方案的完整流程。

Morpho 的核心不是再做一个 AI 生图器，也不是做一个通用白板，而是把用户真实的 ID 设计工作过程整合进同一个画布空间：

```text
没有想法 / 有模糊想法
→ 找方向
→ 调研与参考收集
→ 提炼洞察与设计机会
→ 生成概念方向
→ 快速视觉预览
→ 主效果图反复迭代
→ 锁定主视觉锚点
→ 基于主视觉生成角度图、细节图、场景图、CMF 图等
→ 方案比较与决策记录
→ 根据展板 / PPT / 作品集等交付物整理输出结构和素材
```

Morpho 的主要差异点在于：

1. 用户可以从完全没有方向开始，而不是必须先填写完整 Brief。
2. 概念方向不能只靠文字确认，必须尽早生成快速视觉预览。
3. 主效果图是后续所有视觉素材的锚点；先迭代主视觉，再派生其他图。
4. 全流程中每个阶段都有自己的 AI 上下文窗口和阶段任务，而不是一个聊天窗口跑完整个项目。
5. 每个阶段结束后自动形成阶段交接文档，并更新项目长期记忆，保证后续 AI 能接力。
6. 画布不只是摆图，而是承载调研、方向、图像迭代、比较、输出和过程追溯的主工作区。

## 1. 产品名称与定位

### 1.1 产品名称

**Morpho**

不再纠结中文名。Morpho 本身强调形态变化、演化、从模糊到成形，适合表达 ID 概念设计从无到有、从想法到视觉方案的过程。

### 1.2 一句话定义

**Morpho 是一款面向 ID 外观概念设计全流程的 AI 画布工作台，帮助用户在一个连续画布中完成从“没有想法”到“可展示视觉方案”的设计推进、图像迭代和输出整理。**

### 1.3 更完整的产品定义

Morpho 是一款面向产品设计 / 工业设计学生、设计初学者、早期 ID 设计师与独立设计师的 AI 辅助设计平台。它以无限画布为主工作区，将 AI 对话、方向探索、调研整理、概念生成、视觉预览、主效果图迭代、系列素材生成、方案比较、展板 / PPT / 作品集整理整合到一个项目空间中。

它解决的不是单张图生成问题，而是设计过程割裂问题：用户不需要在 ChatGPT、AI 生图平台、参考图收藏工具、Figma、PPT、文件夹之间来回切换；Morpho 通过画布、阶段 AI 助手和项目记忆系统，让整个 ID 概念设计过程能够被持续推进、记录、追溯和整理。

### 1.4 产品边界

Morpho 做：

- 项目启动与信息倾倒
- 从无方向到项目方向探索
- 前期调研和参考收集
- 用户、场景、竞品、风格、CMF 参考整理
- 洞察与设计机会提炼
- 产品外观概念方向生成
- 各方向快速视觉预览
- 主效果图迭代
- 图像反馈、批注、再生成
- 主视觉锚点锁定
- 多角度图、细节图、场景图、CMF 图、爆炸示意图等系列素材生成
- 方案比较、选择理由、否定方向记录
- 展板 / PPT / 作品集等交付物的结构规划、素材清单、缺失内容分析
- 全流程上下文记忆、阶段交接和过程追溯

Morpho 暂不做：

- 精确 CAD 建模
- 结构工程设计
- 真实机械结构验证
- BOM / 成本核算
- 供应链和制造流程
- 量产工艺
- 企业级 PLM / PDM
- 重型多人协作系统

Morpho 的“全流程”指的是学生和早期 ID 设计师常见的外观概念设计与视觉表达全流程，而不是从概念到量产的完整工业产品开发流程。

## 2. 目标用户与核心场景

### 2.1 核心用户

第一阶段核心用户为：

- 产品设计学生
- 工业设计学生
- 设计初学者
- 早期 ID 设计师
- 独立设计师
- 需要快速完成概念视觉表达的人

这些用户的共同特征：

- 经常从模糊课题或不明确方向开始；
- 需要先讨论、调研、找问题、确定设计方向；
- 不一定有很强的手绘或建模能力；
- 会大量使用 AI 对话和 AI 生图；
- 需要反复改 prompt、改图、对比方案；
- 最终通常要交付展板、PPT、作品集页面或设计说明；
- 痛点不是某个模型不够强，而是工具割裂、过程丢失、上下文断裂、素材难整理。

### 2.2 核心使用场景

1. **课程项目 / Studio Project**
   - 老师给一个宽泛题目，用户需要自己找方向、调研、出概念、做图、做展板。

2. **比赛 / 创意设计项目**
   - 用户有主题或赛题，需要快速发散方向，生成概念图和展示材料。

3. **作品集项目补充**
   - 用户想补一个项目，从方向探索到最终作品集页面都需要 AI 辅助。

4. **个人兴趣概念设计**
   - 用户有一个大概想法，想通过 AI 逐步做成视觉方案。

5. **已有项目的图像迭代与展示整理**
   - 用户已经有方案，需要继续生成效果图、细节图、场景图、PPT 或展板内容。

## 3. 核心价值主张

### 3.1 从工具切换到集成工作台

原来的流程通常是：

```text
ChatGPT 讨论方案
→ 复制 Prompt
→ 去 AI 生图平台生成
→ 下载图片
→ 回聊天窗口分析
→ 再修改 Prompt
→ 再生图
→ 再导入 Figma / PPT / 展板
```

Morpho 试图把这些动作放入一个连续项目空间。

### 3.2 从结果图到设计过程

Morpho 不只保存最终图片，还保存：

- 设计方向从哪里来；
- 依据了哪些调研和参考；
- 哪些方向被否定；
- 哪张图来自哪个生成任务；
- 用户喜欢和不喜欢什么；
- 主视觉如何迭代出来；
- 最终素材如何被用于展板或 PPT。

### 3.3 从单轮生成到阶段接力

Morpho 的 AI 不是一个全程混在一起的聊天框，而是多个阶段 AI 助手接力：

- 启动阶段 AI：帮助用户倾倒信息和判断当前状态；
- 探索阶段 AI：帮助无方向用户找到项目方向；
- 调研阶段 AI：帮助收集竞品、用户、场景、参考；
- 定义阶段 AI：帮助提炼洞察、机会和设计定位；
- 预览阶段 AI：帮助概念方向快速视觉化；
- 迭代阶段 AI：帮助主效果图反复修改到满意；
- 扩展阶段 AI：帮助从主视觉派生系列素材；
- 比较阶段 AI：帮助方案评估和决策记录；
- 交付阶段 AI：帮助展板、PPT、作品集整理输出。

### 3.4 从短期上下文到项目记忆

Morpho 通过阶段交接文档、项目长期记忆、自动上下文压缩和素材索引，让 AI 能在长流程中持续理解项目，而不是每个阶段重新开始。

## 4. 完整用户流程

Morpho 的流程不是独立页面流，而是一个画布中的阶段推进流。用户可以通过左侧导航定位不同阶段，也可以在画布中自由拖拽、补充和回看。

### 4.1 New Project：极简创建项目

创建项目不要求用户填写完整信息。

流程：

```text
点击 New Project
→ 直接进入空白 Morpho Canvas
→ AI 侧边栏提示：你可以从一句话、一张图、一个文件、一个模糊想法，甚至“我不知道做什么”开始。
```

原因：很多用户最开始并不知道项目名称、产品类别、目标用户和交付物。如果创建项目时要求填大量字段，会违背 Morpho 支持“从无想法开始”的定位。

### 4.2 Start：信息倾倒 / 初始讨论

用户可以输入或上传任何内容：

- 一句话想法；
- 课程要求；
- 竞赛题目；
- PDF；
- 参考图；
- 截图；
- 草图；
- 之前聊天记录；
- 模糊需求；
- “我不知道做什么”。

系统目标：

- 判断用户当前状态；
- 建立初始项目上下文；
- 整理已有信息与未知问题；
- 给出下一步路径建议。

AI 可以询问：

```text
你现在更接近哪种状态？
A. 完全没有想法，只知道要做一个设计项目
B. 有一个宽泛方向，但不知道做什么产品
C. 已经知道产品类别，想继续深入
D. 已经有方案，想做图像和展示
```

### 4.3 Explore：方向探索 / 分流

Start 后进入分流。

如果用户已有大概方向，则进入 Research。  
如果用户完全没有方向，则先进入 Explore。

Explore 的任务是从宽泛主题中生成多个可行项目方向，例如：

```text
方向 1：校园共享空间中的便携收纳产品
方向 2：老年人夜间如厕安全辅助产品
方向 3：宠物家庭清洁与收纳产品
方向 4：户外轻量化饮水与携行产品
```

每个方向应说明：

- 为什么值得做；
- 适合什么用户；
- 可能的产品类型；
- 可视化潜力；
- 调研难度；
- 课程展示潜力；
- 后续展开空间。

输出：

- 项目方向候选；
- 最终确定或暂定方向；
- 后续调研问题。

### 4.4 Research：调研与参考收集

确定方向后，进入调研。

用户可以：

- 上传竞品图；
- 上传参考图；
- 导入资料；
- 让 AI 查询或整理竞品方向；
- 让 AI 分析用户场景；
- 让 AI 总结参考图风格；
- 收集 CMF、材质、形态、场景参考。

画布上形成：

- 竞品参考区；
- 用户场景区；
- 问题现象区；
- 风格参考区；
- CMF 参考区；
- 类似产品区。

Research 不是为了生成长篇论文式调研，而是服务后续 ID 设计判断：

```text
我做什么？
为什么做？
大概长什么样？
现有产品哪里不好？
我可以从哪些风格、结构、场景中借鉴？
```

### 4.5 Frame：洞察、机会与设计定义

AI 基于调研内容帮助用户整理：

- 痛点；
- 用户需求；
- 场景问题；
- 设计机会；
- 产品定位；
- 形态关键词；
- 风格关键词；
- 材质倾向；
- 设计约束。

输出示例：

```text
设计机会 1：让老人起身时更容易找到稳定支撑点。
设计机会 2：让卫浴辅助产品看起来不那么医疗化。
设计机会 3：减少安装和施工难度。
```

Frame 的目标是把调研转成后面可以生成视觉方向的设计定义。

### 4.6 Preview：概念方向 + 快速视觉预览

概念方向不能只用文字让用户决定。Morpho 应该尽早将概念方向视觉化。

流程：

```text
基于 Frame 阶段生成 3–5 个概念方向
→ 每个方向附带关键词、定位和简短说明
→ 每个方向生成 2–4 张快速视觉预览图
→ 用户基于文字 + 图像感受选择喜欢的方向
```

这里的图不是最终效果图，而是低成本的方向判断图，用于帮助用户回答：

- 哪个方向更有感觉？
- 哪个方向视觉潜力更大？
- 哪个方向适合继续深入？
- 哪些风格应该保留或否定？

### 4.7 Iterate：主效果图迭代

选定或暂定方向后，进入主效果图迭代。

核心原则：**先把主效果图迭代到满意，再生成后续三视图、细节图、场景图。**

流程：

```text
选择一个视觉方向
→ 生成第一批主效果图
→ 用户挑选喜欢的图
→ 用户反馈：哪里好、哪里不好、想怎么改
→ AI 继续生成变体
→ 反复迭代
→ 锁定主视觉锚点
```

主视觉锚点保存：

- 最终主效果图；
- 最终 prompt；
- 相关参考图；
- 用户反馈记录；
- 被保留原因；
- 被否定方向；
- 当前设计关键词；
- 当前视觉风格和 CMF 方向。

重要修正：不要在主效果图满意前一次性生成所有后续任务卡。因为主效果图迭代过程中，方案可能会偏离最初描述。后续图像任务应该以最终主视觉锚点为依据重新生成。

### 4.8 Extend：基于主视觉生成系列素材

当主视觉锚点确定后，再生成下游素材任务：

- 正视图；
- 侧视图；
- 背视图；
- 多角度图；
- 细节特写图；
- 使用场景图；
- CMF 配色图；
- 爆炸示意图；
- 尺寸 / 结构展示图；
- 展板主视觉图。

这些任务卡应基于最终主视觉动态生成，而不是在概念早期预设。

### 4.9 Compare：方案比较与决策记录

用户可以比较：

- 多个方向；
- 多个主视觉候选；
- 多个配色方案；
- 多个场景图版本；
- 多个细节处理方式。

AI 可以帮助分析：

- 哪个更符合项目目标；
- 哪个视觉表达更强；
- 哪个更适合展板；
- 哪个更符合用户痛点；
- 哪些方向被否定；
- 哪些局部值得保留。

用户可以标记：

- 主方案；
- 备选；
- 淘汰；
- 保留局部；
- 保留风格；
- 仅作参考。

Compare 阶段的价值不只是选图，而是记录为什么这样选。

### 4.10 Deliver：交付物选择与输出整理

最后不默认“展板 + PPT 一起整理”，而是让用户选择交付物，可多选：

- 展板；
- PPT；
- 作品集页面；
- 图像素材包；
- 报名帖；
- 视频脚本；
- 其他。

选择展板时：

```text
选择展板
→ AI 根据前面所有内容分析展板怎么做
→ 输出展板结构
→ 用户确认 / 修改
→ AI 生成每个模块所需内容和图片清单
→ 判断已有素材与缺失素材
→ 生成展板参考图 prompt
→ 可尝试生成展板视觉参考图
```

选择 PPT 时：

```text
选择 PPT
→ 输入页数 / 汇报时长 / 使用场景
→ AI 根据整个项目生成 PPT 框架
→ 用户确认 / 修改
→ 每页生成标题、内容、图像建议
→ 判断是否需要后续自动生成 PPT 或 PPT 参考图
```

Deliver 阶段第一重点不是直接生成最终 PPT，而是先整理结构、素材、图注、缺失内容和输出策略。

## 5. 工作台信息架构

Morpho 用户可见界面不应拆成很多页面。核心结构应是：

```text
项目首页
→ 项目工作台
→ 输出 / 导出面板
→ 设置，可选
```

### 5.1 项目首页

项目首页用于：

- 新建项目；
- 查看最近项目；
- 搜索项目；
- 打开项目。

新建项目应极简：点击即可进入，不强迫填表。

### 5.2 项目工作台

项目工作台是 Morpho 的核心界面。

布局：

```text
顶部栏：项目名 / 保存状态 / 模型 / 导出 / 设置
左侧：可展开 / 收起的阶段导航与资产入口
中间：无限画布
右侧：当前阶段 AI 助手 / 属性面板
底部：生成队列 / 生成历史 / 来源链路
```

### 5.3 左侧导航

左侧不应一直是重型侧边栏，而是可收起导航。

收起状态显示阶段图标或阶段点：

```text
Start
Explore
Research
Frame
Preview
Iterate
Extend
Compare
Deliver
```

点击后定位到画布对应阶段区域。

展开状态显示：

- 阶段列表；
- 当前阶段进度；
- 阶段成果；
- 资产入口；
- 记忆 / 文档入口；
- 输出入口。

### 5.4 中央画布

画布是主工作区，阶段不是独立页面，而是画布上的区域。

默认阶段区域：

```text
Start Space
Explore Space
Research Wall
Frame Board
Concept Preview
Visual Iteration
Asset Extension
Compare Board
Deliver Planning
```

每个阶段区域可以被折叠成摘要块，但不会消失。用户可以回看和跳转。

### 5.5 右侧 AI 面板

右侧 AI 面板根据当前阶段切换模式。

结构：

```text
Current Stage
Current Context
Suggested Actions
Chat
Memory Status
Object Properties
```

右侧 AI 不是单纯聊天框，而是阶段助手 + 当前选中对象属性面板。

不同对象被选中时，快捷操作不同：

- 选中 Research：总结洞察、聚类问题、提炼机会；
- 选中 Concept：生成视觉预览、扩展方向、找参考；
- 选中 Image：生成变体、改材质、生成角度图、分析问题；
- 选中 Compare：对比方案、推荐方向、生成决策说明；
- 选中 Deliver：整理展板结构、生成 PPT 大纲、列缺失素材。

### 5.6 底部栏

底部栏主要用于：

- 生成队列；
- 生成历史；
- 当前对象来源链路。

来源链路示例：

```text
image_023 主效果图
← visual_task_014 主视觉迭代任务
← concept_03 家居化低医疗感方向
← insight_06 避免医疗器械感
← research_group_02 老人卫浴辅助竞品
```

## 6. AI 上下文与项目记忆系统

### 6.1 基本原则

Morpho 不能用一个聊天窗口跑完整项目。完整流程很长，如果所有内容都留在同一个上下文中，会出现混乱、遗忘、速度变慢和上下文爆炸。

正确方式是：

```text
一个阶段一个 AI 上下文窗口
每个阶段有自己的 System Prompt
阶段结束自动生成交接文档
项目长期记忆持续更新
后续阶段读取项目长期记忆 + 上阶段交接 + 当前选中画布对象
```

### 6.2 分阶段 System Prompt

每个阶段 AI 都有不同职责。

示例：

```text
Explore 阶段：
你是 Morpho 的项目方向探索助手，帮助用户从无想法或宽泛要求中找到适合 ID 外观设计表达的项目方向。

Research 阶段：
你是 Morpho 的设计调研助手，帮助用户整理竞品、用户场景、痛点、参考图和风格资料。

Preview 阶段：
你是 Morpho 的概念视觉方向助手，帮助用户把多个概念方向快速视觉化，不要求最终效果图，只帮助判断方向潜力。

Iterate 阶段：
你是 Morpho 的主效果图迭代助手，帮助用户基于反馈反复调整图像，直到形成主视觉锚点。

Deliver 阶段：
你是 Morpho 的展示整理助手，帮助用户根据项目全过程整理展板、PPT 或作品集结构。
```

### 6.3 上下文输入结构

每次调用阶段 AI 时，系统自动组装：

```text
阶段 System Prompt
+ 项目长期记忆
+ 上一阶段 Handoff
+ 当前阶段压缩上下文
+ 当前画布选中对象
+ 用户最新输入
```

不要默认让 AI 读取整个画布。AI 的画布理解应以当前阶段、当前区域、当前选中对象、用户指定对象为边界。

### 6.4 自动上下文压缩

上下文压缩应该自动发生，不需要用户主动点击。

触发时机：

1. 当前阶段聊天过长；
2. 用户切换阶段；
3. 用户做出关键决策；
4. 用户明确否定某方向；
5. 用户锁定主视觉；
6. 系统即将进入交付整理。

用户最多看到轻提示：

```text
已自动整理当前阶段记忆。
已记录该设计决策。
已更新项目偏好。
已生成阶段交接摘要。
```

可以保留手动入口，但不叫“压缩上下文”，而叫：

```text
更新项目记忆
整理当前阶段
生成阶段总结
```

### 6.5 阶段 Handoff 文档

每个阶段结束后自动生成一个阶段交接文档。建议使用 Markdown + YAML frontmatter。

阶段文档包含 8 类内容：

1. 阶段目标与当前状态；
2. 本阶段产出成果；
3. 关键设计决策与原因；
4. 被否定方向与原因；
5. 用户偏好与反感点；
6. 项目约束与稳定设定；
7. 未解决问题与风险；
8. 下一阶段接力指令。

### 6.6 项目 Living Memory

除了阶段 Handoff，系统还维护贯穿项目的长期记忆文档。

建议结构：

```text
living_memory/
  project_overview.md
  design_brief.md
  user_preferences.md
  decision_log.md
  rejected_directions.md
  open_questions.md
  output_plan.md
```

区别：

- Stage Handoff 是历史快照，记录某阶段发生过什么；
- Living Memory 是当前项目档案，记录跨阶段稳定信息。

阶段文档不要频繁改，长期记忆会持续更新。

### 6.7 文档与数据格式分工

Markdown：

- 给人和 AI 读的正文；
- 用于阶段总结、设计决策、项目记忆、输出计划。

YAML：

- 写在 Markdown 顶部；
- 用于标记阶段、状态、关联素材、更新时间等元数据。

JSON：

- 给系统读；
- 用于画布对象位置、素材索引、生成历史、prompt、图片关系、线程状态等结构化数据。

## 9. 目前已经确定的关键原则

1. **项目可以从空白开始。**
   - 创建项目不要求填写完整信息。
   - 用户可以从“我不知道做什么”开始。

2. **方向确认必须图像化。**
   - 概念方向不能只靠文字决定。
   - 每个方向应配快速视觉预览。

3. **主效果图是后续素材锚点。**
   - 先反复迭代主效果图。
   - 锁定主视觉后，再生成三视图、细节图、场景图等。

4. **阶段 AI 接力，而不是单一超长聊天。**
   - 每个阶段有自己的 AI Thread 和 System Prompt。
   - 阶段间通过 Handoff 文档和 Living Memory 交接。

5. **上下文压缩自动进行。**
   - 用户不需要手动点。
   - 用户最多看到“已自动更新项目记忆”之类提示。

6. **画布是主工作区，不是纯展示板。**
   - 画布承载资料、洞察、方向、图像、比较和输出。

7. **过程可追溯是核心价值。**
   - 每张图、每个方向、每个决策都应能追溯来源和原因。

# 交接到下一个窗口的 Prompt

下面这段可直接复制到下一个 ChatGPT 窗口，用来继续 Morpho 产品设计：

```text
我正在设计一个名为 Morpho 的产品。请先完整接收以下项目上下文，不要急着发散。

Morpho 是一款面向 ID 外观概念设计全流程的 AI 画布工作台。这里的“全流程”不是包含 CAD、结构工程、制造、量产的工业设计商业全流程，而是面向产品设计 / 工业设计学生、设计初学者、早期 ID 设计师和独立设计师的外观概念设计与视觉表达全流程。

Morpho 的核心流程是：
没有想法 / 有模糊想法 → 找方向 → 调研与参考收集 → 提炼洞察与设计机会 → 生成概念方向 → 快速视觉预览 → 主效果图反复迭代 → 锁定主视觉锚点 → 基于主视觉生成角度图、细节图、场景图、CMF 图等 → 方案比较与决策记录 → 根据展板 / PPT / 作品集等交付物整理输出结构和素材。

重要定位：
1. Morpho 不是 AI 生图器，而是一个 ID 概念设计过程工作台。
2. Morpho 不是 CAD / 结构 / 量产工具，不处理工程落地。
3. Morpho 可以从完全没有方向开始，创建项目时不要求填写完整 Brief。
4. 创建项目应极简：点击 New Project 直接进入空白画布。
5. 用户可以输入一句话、上传课程要求、PDF、参考图、截图、草图，也可以直接说“我不知道做什么”。
6. 如果用户已有方向，进入深入调研；如果用户没有方向，先进入方向探索。
7. 概念方向不能只靠文字确认，必须给每个方向配快速视觉预览图，让用户基于文字 + 图像选择方向。
8. 不要在早期一次性生成所有 Prompt / 任务卡。真实流程是先迭代主效果图，直到满意后锁定主视觉锚点，再基于主视觉生成三视图、细节图、场景图、CMF 图、爆炸示意图等系列素材任务。
9. 最后 Deliver 阶段让用户选择交付物，可以多选：展板、PPT、作品集页面、图像素材包、视频脚本等。每种交付物先做结构分析、素材清单和缺失内容判断，再考虑生成具体内容或参考图。

Morpho 的阶段流暂定为：
Start / 启动：信息倾倒、上传资料、自由讨论、判断用户状态。
Explore / 探索：无方向时寻找项目方向；有方向则跳过或弱化。
Research / 调研：收集竞品、用户、场景、风格、CMF、参考图。
Frame / 定义：提炼痛点、设计机会、产品定位、形态关键词、风格关键词。
Preview / 预览：生成多个概念方向，并为每个方向生成快速视觉预览。
Iterate / 迭代：围绕选定方向反复生成和修改主效果图，直到锁定主视觉锚点。
Extend / 扩展：基于主视觉生成角度图、细节图、场景图、CMF 图等系列素材。
Compare / 比较：比较方案、记录保留 / 淘汰 / 主方案 / 备选和选择理由。
Deliver / 交付：选择展板、PPT、作品集等输出形式，整理结构、素材和缺失内容。

界面结构：
用户可见页面尽量少，主要是：项目首页 → 项目工作台 → 输出 / 导出面板。项目工作台是核心。
工作台布局：顶部栏 + 左侧可收起阶段导航 + 中央无限画布 + 右侧当前阶段 AI 助手 / 属性面板 + 底部生成队列 / 历史 / 来源链路。
左侧导航收起时只显示阶段点或图标，点击可定位到画布对应区域；展开时显示阶段、进度、资产和文档入口。
中间画布不是单纯摆图，而是承载 Start、Explore、Research、Frame、Preview、Iterate、Extend、Compare、Deliver 等阶段区块。
右侧 AI 面板不是一个全局万能聊天框，而是当前阶段 AI 助手。不同阶段有不同 System Prompt 和任务重点。
底部栏显示生成队列、生成历史和当前选中对象的来源链路。

AI 上下文机制：
Morpho 不应该一个聊天窗口跑完整项目，而是一个阶段一个 AI Thread。每个阶段有自己的 System Prompt。阶段中如果对话过长，系统自动上下文压缩，用户不需要手动点。阶段切换时，系统自动生成阶段 Handoff 文档，并更新项目 Living Memory。
后续阶段 AI 的上下文由以下内容组成：阶段 System Prompt + 项目长期记忆 + 上一阶段 Handoff + 当前阶段压缩上下文 + 当前画布选中对象 + 用户最新输入。
AI 不应默认读取整个画布，而应基于当前阶段、当前区域、用户选中对象或指定分组理解上下文。

项目记忆结构：
使用“阶段 Handoff 文档 + 项目 Living Memory”的混合结构。
阶段 Handoff：按阶段分，一阶段一个 Markdown 文档，记录历史过程。
Living Memory：按类型分，持续更新，记录整个项目当前稳定信息。
阶段 Handoff 文档包含 8 类内容：
1. 阶段目标与当前状态
2. 本阶段产出成果
3. 关键设计决策与原因
4. 被否定方向与原因
5. 用户偏好与反感点
6. 项目约束与稳定设定
7. 未解决问题与风险
8. 下一阶段接力指令

Living Memory 建议包含：
project_overview.md、design_brief.md、user_preferences.md、decision_log.md、rejected_directions.md、open_questions.md、output_plan.md。
Markdown 用于给人和 AI 读的正文；YAML frontmatter 用于给 Markdown 加阶段、状态、关联素材等元数据；JSON 用于系统数据，如画布位置、素材索引、生成历史、prompt、图片关系、线程状态等。

请基于以上上下文继续帮我推进 Morpho。下一步我想重点讨论：完整产品方案文档的进一步完善、每个阶段的画布结构、右侧 AI 面板的操作设计、卡片类型、功能优先级、以及后续原型 / 开发规划。请不要把 Morpho 理解成普通 AI 生图工具，也不要把它扩大成结构工程和量产平台。
```
