# Morpho Design Agent 工程现状、开源对标与首轮迭代建议

2026-11-16 · 工程研究与产品决策参考

**建议保留 A+ Runtime，先在现有任务合同内改进设计方法与结果观察。** 最先做一组概念方向 Method Pack 对照，并把实际送出的方法、工具和资料覆盖固定在现有测试里。并行用固定响应查清两个具体问题：当前资料与旧判断冲突时，模型实际拿到了什么；生成后要求评阅时，原图和结果图是否实际进入同一个 continuation。Pi Core 是后续最值得保留的嵌入式候选。只有把当前瓶颈定位到循环调度，并证实替换能删掉实际维护的编排代码，才值得做适配验证。

### Prompt、方法、记忆与调试

- **Prompt 组装。** 真正发给 Provider 的顺序由 `buildAPlusAgentProviderContract` 决定，包含稳定 System（当前 `morpho-agent-v3.8-2026-10-01`）、Runtime Item、任务合同、活动策略、Method Pack、请求资料与续传 items。正式含合同的请求由服务端重新推导方法，不接收客户端指定的有效方法正文。默认用活动和措辞选择去重后最多三包。稳定策略已经明确证据、假设和设计变量，出图另经 `morpho-image-prompt-v4` 编译。[稳定 Prompt](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/shared/agentPromptRegistry.ts) · [策略](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/shared/agentStrategyItem.ts) · [选择规则](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/shared/designMethodPack.ts#L157) · [服务端组装](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/server/ai/agentTurnProviderRequest.ts#L184) · [图像编译](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/domain/operations/imagePromptCompiler.ts)
- **项目事实与会话。** 一个连续项目会话保留 summary boundary 之后合格的历史，阶段/方向/选区影响资料与方法，当前结构化工作状态与来源优先。Memory Kernel 是可追溯的当前投影，吸收确认或用户明确资料，阶段记录有自己的 current revision，详细历史按需用工具查。输入快照和初始 Frame 保存当时给模型的文本/覆盖及图像标识，续传可追加 fresh context。快照、摘要和读回执分别回答当时拿到什么、讨论压缩到哪里、指定资料是否真正送达。[任务上下文](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/features/workspace/taskContext.ts) · [Memory Kernel](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/domain/morpho/projectMemory.ts) · [输入快照](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/domain/morpho/providerInputSnapshot.ts) · [Context Frames](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/features/workspace/providerContextFrames.ts) · [读取覆盖](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/features/workspace/agentSourceReads.ts#L92)
- **Compaction。** Morpho 固定 256k window、204.8k prepare、230.4k compact、16k target。自动模式在合适边界调用压缩，`/compact` 走独立摘要流程，校验来源、边界和旧 summary revision 后写入新摘要。服务端遇明确上下文超限另有有界的应急压缩重试。遇传输不明则沿执行日志观察，避免把压缩、兼容重试和普通重发混为一谈。[预算](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/domain/morpho/agentContextPolicy.ts) · [自动与手动压缩](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/features/workspace/agentCompactionOrchestrator.ts) · [外部压缩](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/app/api/ai/agent/turns/%5BturnId%5D/actions/compaction/handler.ts) · [Provider 重试边界](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/server/ai/openaiCompatibleProvider.ts)
- **今天能怎样换一件东西。** 改 System 一般在 Registry；改一包方法正文通常只需改共享文件。改选择行为则要同时查活动合同和服务端实际 Prompt。当前 A+ parser 只接受一个约定版本，同版本换正文会使取证时的标签无法区分变体。Provider 地址/模型等已有服务端环境配置，图片有独立设置。正式入口未见按项目或单轮选择 Prompt/Method/Tool 变体的实验面。比较最短路径是提交身份或离线 fixture 标明变体，用现有 `buildAPlusAgentProviderContract` 取有效组装，并用 `agentTurnHostFake` / Runner fixtures 固定调用与失败，不启用真实探针。新增或替换真实工具通常要同步 schema、解析、注册、合同归属和权限。只改一个只读工具的实现时，复用既有接口即可。[版本校验](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/server/ai/agentTurnProviderRequest.ts#L86) · [模型配置](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/server/ai/openaiCompatibleConfig.ts) · [模拟 Host](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/features/workspace/agentTurnHostFake.ts) · [Runner fixtures](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/src/features/workspace/agentTurnRunner.test.ts) · [真实 Responses 探针源码](https://github.com/Whatnamed/Morpho/blob/d772f0cfbce30a328680655dee40f9694d1fa4ee/scripts/probe-agent-responses-stream.mjs)

## 4. 复用选择

| 适配判断 | 可拿来的机制 | Morpho 接入和维护成本 |

| **现在直接使用** | Morpho 自有 Prompt Registry、Method Pack、真实服务端组装函数、Host Fake 与固定响应；用 Pi 的显式宿主输入、OpenDesign 的输入冻结思想安排对照。 | 低。以 fixture 或明确的 Git 变体标识实际策略/方法、工具集合和证据覆盖。无需引入包或运行时配置。可把“方法没选中”和“选中了但模型没用”分开追查。 |

## 6. 首轮建议与轻量验证

| 顺序 | 改进候选、收益目标与依赖 | 预计范围与验证 |

| **1 · 一包方法的短对照** | 对 BC002 在相同资料上比较现有概念发散包与一份短变体，突出「现有证据 → 人的动作/能量输入 → 功能原理与接口 → 尚缺验证」，保留多条可推进候选。目标是减少原理重复并提高理由可核性。前提是现有活动实际选中这包、两组工具与候选数相同。 | 主要动 `shared/designMethodPack.ts` 和一组服务端/固定响应 fixture。记录 Git 身份和实际 Provider method block。先验三方向与授权、资料覆盖，后由用户盲选哪组更值得推进并说明一个具体理由。若变体只增加篇幅或耗时，保留原包。 |

**轻量执行顺序。** 未来独立执行时先跑上述三条固定响应。只保留能够指出可观察差异的对照，然后优先选择第 1 项做一次小范围配对人工评阅。对照固定模型与后端、同一 case 和资产、授权、总预算及候选数，每次只改变一个被解释的因素。记录实际方法/输入覆盖、调用数、耗时与故障；条件允许时记录实耗，未知费用保留未知。确定性检查与专业判断各自记录。用户可选 A、B、平局或证据不足，并给一句理由；回归、丢失约束和越权独立列出，无需 LLM Judge，也不把单例结果外推。新一次真实 Provider 测试属于后续执行范围。

**现在能推进的工程准备。** 用现有测试固定 case 输入和有效 Provider 合同，试单包内容、限定修订资料是否当前、同轮观察可达性。这些实验不需要先决定新 Loop 或产品界面。若结果指向用户未发现选择/来源范围、观察与再生成的动作边界，交给产品负责人定下一轮交互。何时自动反复生成、是否提供完整 Skill 管理、如何做 RAG/专业工具架构或 Multi-Agent，需要相应产品与 UX 决策以及适用的数据、工具与评审证据。

## 7. 推荐决策与研究限制

保留 A+，先批准一个 **BC002 单方法对照**，用 BC008、BC006 的固定响应同时确认资料及观察链。结果能说明下一步该改方法、补资料还是动调度。如果同等信息与预算下反复出现可定位的循环编排问题，再以 Pi Core 做只读工具的最小适配验证，观察能否减少现有驱动职责。

本轮只做定点源码核查、历史证据复读和 Morpho 离线测试。未启动第三方应用或验证其安装、真实适配和版本发布状态，未执行付费调用、旧 P7 或用户设计评阅。设计质量、实际时延和 SDK 迁移成本仍待实测。
