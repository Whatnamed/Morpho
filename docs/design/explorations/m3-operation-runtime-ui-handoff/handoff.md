# Morpho M3 — Operation Runtime UI 交接说明

> **用途**：本文档面向 M3 Operation Runtime 的正式实现者（Codex）。它只描述交互原型 `index.html` 中的视觉与交互规则，以及对应的技术映射建议。它不是产品规则文档，不覆盖 `docs/product/00–05` 中的任何定义。
>
> **范围**：`chatAnalysis`、`imageGeneration`、`researchOperation` 三种 taskMode 的视觉呈现、Operation 状态显示、ArtifactProposal 草案确认流程、SourceCitation 来源引用展示、左侧抽屉与画布空白的交互规则、图片比例的视觉规则。
>
> **优先级**：产品行为以 `docs/product/` 为准；视觉语言以 `Morpho_Light_Design_System_v1_CN_EN.md` 为准。本文档只在两者未覆盖的 Operation Runtime 细节上提供实现建议。

## 1. 每个场景对应的用户目标

| 场景 | 用户目标 | 原型中的表现 |
|---|---|---|
| 01 默认对话与分析 | 选中一张图后，想理解它而不是立刻生成新图 | taskMode = `对话与分析`；不显示任何生图控件；建议 chip 只填入输入框 |
| 02 明确图像生成 | 已决定继续发展图像，需要明确模式和轻量设置 | taskMode = `图像生成`；显示生成类型 / 模型级别 / 比例 / 清晰度 / 参考图数；生成进度嵌在聊天中 |
| 03 研究任务 | 选中多份资料后，想整理一轮前期调研 | taskMode = `研究任务`；多步 Operation 进度嵌在聊天中；可取消；显示联网状态 |
| 04 草案确认 | 研究任务完成后，想审阅草案再决定是否保存 | 草案卡出现在聊天中；草案 ≠ 画布对象；只有点击「保存为研究与分析」后才创建正式对象 |
| 05 失败与中断 | 任务失败 / 用户取消 / 来源变化时，不丢失已有工作 | 状态卡明确说明已保留 / 未完成 / 是否可重试；不全屏报错 |
| 06 抽屉与比例 | 理解左侧抽屉关闭逻辑和图片比例展示规则 | 抽屉可开合；画布空白点击收起抽屉并清除选择；三种比例图片 contain 显示 |

## 2. 关键组件与状态

### 2.1 AI 面板（连续对话层）

AI 面板是浮在画布右下的连续对话表面，**不是**对象属性检查器。它的结构从上到下：

```
面板顶栏（标题 + 收起按钮）
taskMode 切换条（对话与分析 / 图像生成 / 研究任务 + Context 标签）
对话滚动区（消息 / Operation 进度 / 草案卡 / 状态卡 / 建议 chip）
输入区（输入框 + 发送按钮 + 模式提示）
```

**关键约束**：
- 面板宽度 `442px`，高度 `min(62vh, 580px)`，锚定右下角。
- 面板覆盖画布，不挤压画布宽度。
- 收起后变成右下角紧凑浮动入口。
- 点击画布空白**不会**关闭 AI 面板——它始终是连续对话层。

### 2.2 taskMode 切换条

位于面板顶栏下方，由三个 chip 和一个 Context 标签组成：

```
[对话与分析] [图像生成] [研究任务]    [柔光轨道 v2 ×]
```

- 当前模式 chip 使用 `--accent-brand-soft` 底 + `--accent-brand` 文字。
- Context 标签使用 `--accent-select-soft` 底 + `--accent-select` 文字，可移除（点击 ×）。
- 移除 Context 标签只影响 AI 上下文，不影响画布选中状态。

### 2.3 画布对象类型

原型中出现的画布对象及其视觉区别：

| 对象 | 视觉表现 | 数据特征 |
|---|---|---|
| 图片（image-tile） | 图像优先，下方仅角色标签 + 标题 + 元信息 | 有 `ratio` 属性决定比例 |
| 文字资料（file-card） | 文件图标 + 标题 + 类型元信息 | 与图片使用不同卡片壳 |
| 链接（link-card） | favicon + 域名 + 标题 + 抓取状态 | 与文件卡视觉区分 |
| 研究与分析（research-obj） | 编辑文档感，分节内容 | 保存后才出现 |
| 设计定义（definition） | 左侧品牌色竖线 + 文档式排版 | 重要但不抢眼 |
| 概念方向（direction） | 紧凑策略卡 + 关键词 | 轻量，是路线起点 |

### 2.4 底部详情栏

- 仅在选中对象后出现，浮在底部中央。
- 紧凑显示：对象名称 + 关键操作（继续发展图像 / 调研已选资料 / 询问 AI）。
- 多选时显示「已选 N 项资料」。
- 不展开成全高属性面板。

## 3. taskMode 的视觉呈现和切换原则

### 3.1 三种模式

| 模式 | UI 标签 | 何时使用 | 显示的控件 |
|---|---|---|---|
| `chat` | 对话与分析 | 默认模式；选中对象后想理解、比较、讨论 | 仅对话消息 + 建议 chip；**不显示**任何生图控件 |
| `image` | 图像生成 | 用户明确点击「继续发展图像」或主动切换 | 轻量设置面板 + 生成进度 |
| `research` | 研究任务 | 用户选中多份资料后点击「调研已选资料」或输入调研指令 | Operation 进度卡 / 草案卡 / 状态卡 |

### 3.2 切换原则

1. **默认永远是 `对话与分析`**。选中图片后输入「分析这张图」不会自动切换到图像生成。
2. **图像生成必须由用户明确触发**：点击「继续发展图像」、点击 mode chip「图像生成」、或输入明确的生图意图。
3. **研究任务由多选资料 + 调研指令触发**。单选对象时不会进入研究任务。
4. 切换模式只改变 AI 面板内容，**不切换画布视图、不切换聊天线程、不切换项目区域**。
5. 模式切换不自动发送消息、不自动生成、不自动改变项目状态。

### 3.3 输入区提示

输入框下方始终显示当前模式提示：

```
[对话与分析]  建议只填入输入框，不会自动发送
```

这帮助用户理解：建议 chip 的行为是填充而非执行。

## 4. Operation 状态如何显示

### 4.1 进度嵌在聊天中，不做独立任务中心

Operation 进度以卡片形式出现在 AI 面板的对话滚动区内，与普通消息同级。**不**做独立的任务中心页面、侧边任务列表或全屏进度页。

### 4.2 进度卡结构

```
┌─────────────────────────────────────┐
│  任务标题                  [状态标签]  │
│                                     │
│  ✓ 步骤一（已完成）                   │
│  ✓ 步骤二（已完成）                   │
│  → 步骤三（进行中，脉冲动画）          │
│  ○ 步骤四（待执行）                   │
│  ○ 步骤五（待执行）                   │
│                                     │
│  ─────────────────────────────────  │
│  [联网状态]          [取消] [重试]    │
└─────────────────────────────────────┘
```

### 4.3 步骤状态视觉

| 状态 | 图标 | 文字颜色 | 动效 |
|---|---|---|---|
| 已完成（done） | 实心圆 + 白色对勾，`--success` 底 | `--text-secondary` | 无 |
| 进行中（running） | 实心圆，`--accent-select` 底 | `--text-primary`，加粗 | 1.4s 脉冲透明度 |
| 待执行（pending） | 空心圆，`--surface-muted` 底 + 边框 | `--text-muted` | 无 |
| 失败（failed） | 实心圆，`--danger` 底 | `--danger` | 无 |

### 4.4 状态标签

位于进度卡右上角：

| 状态 | 样式 | 文案 |
|---|---|---|
| running | `--accent-select-soft` 底 | 进行中 / 生成中 |
| done | `--success-soft` 底 | 已完成 / 草案已准备 |
| failed | `--danger-soft` 底 | 失败 |
| cancelled | `--surface-muted` 底 | 已取消 |

### 4.5 联网状态

进度卡底部左侧显示联网状态，区分两种情况：

- **本次未联网**：灰色点 + `--text-muted` 文字。对应未授权联网或用户选择不联网。
- **已补充来源**：绿色点 + `--success` 文字。对应已授权联网并补充了来源。

这直接对应产品规则：研究结果必须可回看来源，联网状态必须明确。

### 4.6 可取消与可重试

- 进行中：显示「取消」按钮。取消后保留已完成步骤和已选资料。
- 失败后：显示「重试」「修改后重试」。重试使用当前选中的资料。
- 取消后：显示已保留内容，可重新提交。

### 4.7 不展示模型思维链

进度卡只展示用户能理解的业务步骤（「正在阅读参考图」「正在归纳问题线索」），**不**展示模型内部思维链、Token 消耗、Prompt 详情或模型路由。

## 5. 草案、确认、正式对象的视觉区别

这是 Operation Runtime 中最重要的数据完整性规则。

### 5.1 三种状态的视觉层级

| 状态 | 位置 | 视觉 | 数据含义 |
|---|---|---|---|
| **草案（ArtifactProposal）** | AI 聊天区 | `draft-card`：品牌色浅底头部 + 分节正文 + 来源区 + 操作按钮；头部标注「未保存」 | 候选内容，**未写入画布**，未创建正式对象 |
| **已确认（保存后）** | AI 聊天区 | 草案卡底部操作区替换为绿色「已保存」提示 | 已创建正式对象 |
| **正式对象** | 画布 | `research-obj`：编辑文档感卡片，出现在相关资料附近 | 持久化对象，有稳定身份 |

### 5.2 草案卡（draft-card）结构

```
┌─ 品牌色浅底头部 ────────────────────────┐
│  ● 研究分析草案 · 未保存                  │
│  夜间起身路径与扶持需求的前期调研          │
│  一句摘要                                │
├─────────────────────────────────────────┤
│  主要发现                                │
│  · 发现一                                │
│  · 发现二                                │
│  机会点                                  │
│  · 机会一                                │
│  限制 / 约束                             │
│  · 约束一                                │
│  待验证问题                              │
│  · 问题一                                │
├─────────────────────────────────────────┤
│  来源条目                                │
│  [图] 来源标题 · 域名 · 引用片段          │
│  [文] 来源标题 · 本地标识 · 引用片段       │
│  [链] 来源标题 · 域名 · 引用片段          │
├─────────────────────────────────────────┤
│  [保存为研究与分析] [继续追问]            │
│  [修改研究范围]    [放弃草案]             │
└─────────────────────────────────────────┘
```

### 5.3 确认按钮的行为

| 按钮 | 行为 |
|---|---|
| 保存为研究与分析 | 创建正式 `research-obj` 对象，出现在画布相关资料附近；草案卡变为「已保存」状态 |
| 继续追问 | 不保存，在聊天中继续讨论草案内容 |
| 修改研究范围 | 不保存，回到资料选择，可重新提交研究任务 |
| 放弃草案 | 不保存，草案消失，已选资料和输入保留 |

### 5.4 关键规则

- **草案出现 ≠ 写入画布**。草案只存在于聊天区。
- **只有「保存为研究与分析」才创建正式对象**。
- 保存后的研究对象与来源保持**轻量关联**，不画蜘蛛网连线。
- AI 不能自动保存草案、不能自动将草案转为关键结论、不能自动选择主方向。

## 6. 来源引用在聊天、草案、详情中的展示规则

### 6.1 三层展示

| 位置 | 展示方式 | 详细程度 |
|---|---|---|
| 聊天消息 | 消息内文提及来源时，用简短文字引用 | 最简 |
| 草案卡来源区 | 每条来源独立一行，含类型 / 标题 / 域名 / 引用片段 | 完整 |
| 底部详情栏 | 选中正式对象后，详情栏「来源」tab 显示直接来源 | 一层 |

### 6.2 来源条目结构

每条来源包含：

```
[来源类型图标]  来源标题
                域名 或 本地资料标识
                引用片段或简短说明
```

### 6.3 来源类型视觉

| 类型 | 图标底色 | 图标文字 | 说明 |
|---|---|---|---|
| 图片（image） | `--accent-select-soft` + `--accent-select` | 图 | 画布中的参考图 |
| 文字（text） | `--warning-soft` + `--warning` | 文 | 本地文字资料（PDF 提取文字等） |
| 链接（link） | `--accent-brand-soft` + `--accent-brand` | 链 | 联网补充来源 |

### 6.4 规则

- 来源必须可回看。点击来源应能定位到画布中的原始资料。
- 联网来源显示域名；本地资料显示「本地资料 · 类型」。
- 引用片段用引号包裹，帮助用户理解来源与结论的关系。
- 不展示抓取技术细节（HTTP 状态、抓取时间戳等）。

## 7. 左侧抽屉关闭逻辑的交互规则

### 7.1 抽屉与 rail 的关系

- 左侧 rail 是常驻窄工具栏（48px 宽）。
- 点击 rail 上的「项目地图」按钮**切换**抽屉的展开 / 收起。
- 抽屉展开时出现在 rail 右侧（232px 宽）。

### 7.2 关闭逻辑（必须全部实现）

| 触发 | 行为 |
|---|---|
| 点击 rail 当前激活入口（项目地图） | 收起抽屉 |
| 点击画布空白 | 收起抽屉，**同时**可清除对象选择 |
| 按 Esc | 收起抽屉 |
| 点击抽屉内的导航项 | 定位画布到对应区域，收起抽屉 |

### 7.3 不受影响的行为

- **点击画布对象**：正常选中对象，不要求双击。抽屉状态不变（除非点击的是空白）。
- **右侧 AI 面板**：点击画布时**不会**自动关闭 AI 面板。AI 面板始终是连续对话层。
- **抽屉内的导航**：只移动画布到对应区域，不切换页面、不切换聊天线程。

### 7.4 视觉过渡

- 抽屉展开 / 收起使用 `opacity + translateX + scale` 过渡，`180ms`。
- 抽屉使用 `--shadow-popover` + `backdrop-filter: blur(20px)`。

## 8. 图片比例、contain、最小/最大尺寸的视觉规则

### 8.1 三种比例

原型中必须出现并正确展示三种比例的图片：

| 比例 | 原型示例 | image-box 尺寸 |
|---|---|---|
| 横图（landscape） | 柔光轨道 v2 | `260 × 178`（约 3:2），大图 `320 × 219` |
| 竖图（portrait） | 触觉导向截面 | `168 × 224`（约 3:4） |
| 接近方图（square） | 转角连接件 | `196 × 196`（1:1） |

### 8.2 contain 规则

- 所有图片使用 `preserveAspectRatio="xMidYMid meet"`（SVG）或 `object-fit: contain`（img）。
- **不裁切**。图片完整显示在 image-box 内。
- image-box 背景色 `#e6e3de`，在图片比例与 box 不完全一致时提供柔和衬底。

### 8.3 不与文件卡 / 文字卡共享固定高度

- 图片的 image-box 高度由其比例决定，**不**与 file-card、link-card、research-obj 共享同一高度。
- 不同对象类型保留不同视觉处理（见设计系统 §10）。

### 8.4 最大 / 最小尺寸

| 约束 | 规则 |
|---|---|
| 过大图片 | 缩小到合理最大尺寸（大图宽度上限 `320px`） |
| 过小图片 | 保持最小可操作尺寸（宽度下限 `168px`） |
| 常规图片 | 宽度 `196–260px` |

### 8.5 新生成图片的放置

- 生成完成后，新图作为**新对象**出现在来源图右侧附近。
- **不覆盖**来源图。
- 新图使用 `fadeUp` 动画淡入（`400ms`），不弹跳。

## 9. 哪些组件和状态不应进入正式实现

以下内容是原型演示用的，**不应**出现在正式实现中：

| 组件 / 状态 | 原因 |
|---|---|
| 顶部「原型情景」切换条 | 这是原型导航，不是产品功能 |
| 模拟的 Operation 定时器（setTimeout / setInterval） | 正式实现应由真实 Operation Runtime 驱动 |
| 模拟的 AI 回复 | 正式实现应接入真实 Provider |
| 内嵌 SVG 产品图 | 正式实现应使用真实图片资产或生成结果 |
| `scenarioBar` 及其所有逻辑 | 原型独占 |
| 硬编码的草案内容 | 正式实现应由研究 Operation 产出 |
| 模拟的「已补充来源」状态 | 正式实现应由真实联网状态决定 |

### 9.1 不应暴露的技术细节

- Provider 名称、模型 ID、API Key、Base URL
- 模型规格、Token 消耗、Prompt 详情
- 任务队列、内部存储路径、Context 内部结构
- 价格、能力对比、「最便宜」承诺

### 9.2 不应制造的假功能

- PDF 已完整解析（只说「已提取文字」）
- 网页已全文抓取（只说「已抓取摘要」）
- 局部蒙版编辑已实现
- 后台任务永久执行
- 模型思维链展示

## 10. 技术映射建议

以下是原型中的 UI 概念到 M3 技术实现的映射建议。这些是建议，不是产品规则。

### 10.1 chatAnalysis

```
UI 概念：对话与分析模式
         ├─ taskMode = 'chat'
         ├─ 不显示生图控件
         ├─ 建议 chip 只填入输入框
         └─ Context 标签 = 当前选中对象

技术映射：
  ├─ taskMode: 'chatAnalysis'
  ├─ 不触发 Operation，只走普通对话
  ├─ Context 由当前选中对象的 stable identity 提供
  ├─ 建议 chip 是静态文案 + data-fill 属性，点击只更新 input value
  └─ 发送后由 Provider 返回分析文本，不创建 ArtifactProposal
```

**关键边界**：
- chatAnalysis **不能**自动变成 imageGeneration。
- chatAnalysis **不能**自动创建研究与分析对象。
- chatAnalysis 的结果只是聊天消息，不是画布对象。

### 10.2 imageGeneration

```
UI 概念：图像生成模式
         ├─ taskMode = 'image'
         ├─ 轻量设置：生成类型 / 模型级别 / 比例 / 清晰度 / 参考图数
         ├─ 生成进度：准备参考图 → 提交生成 → 等待结果 → 保存到项目
         └─ 完成后新图出现在来源图右侧

技术映射：
  ├─ taskMode: 'imageGeneration'
  ├─ 生成类型 → generationType: continue | newAngle | scene | cmf | detail
  ├─ 模型级别 → modelTier: sketch | balanced（不暴露模型 ID）
  ├─ 比例 → aspectRatio: landscape | portrait | square
  ├─ 清晰度 → clarity: standard | high（high 仅在可用时显示）
  ├─ 参考图数 → 当前选中图片对象的 count
  ├─ 进度 → Operation status（见 10.4）
  └─ 完成后 → 创建新 image 对象，stable identity 独立于来源图
```

**关键边界**：
- 不在 UI 上展示 API Key、Base URL、Provider 内部字段。
- 不把所有服务商模型名堆成模型市场。
- 不写未经验证的价格或能力承诺。
- 新图**不覆盖**来源图——每张 AI 生成图都是新对象。

### 10.3 researchOperation

```
UI 概念：研究任务模式
         ├─ taskMode = 'research'
         ├─ 多选资料 → 调研指令
         ├─ 多步 Operation 进度嵌在聊天中
         ├─ 步骤：整理资料 → 阅读图片 → 归纳线索 → 补充来源 → 整理发现 → 草案准备
         ├─ 联网状态：本次未联网 / 已补充来源
         ├─ 可取消、可重试
         └─ 完成后产出 ArtifactProposal（草案）

技术映射：
  ├─ taskMode: 'researchOperation'
  ├─ 输入：选中对象的 stable identity 列表（图片 / 文字 / 链接）
  ├─ Operation steps:
  │    1. organizeMaterials   — 整理已选资料
  │    2. readImages          — 阅读参考图
  │    3. induceClues         — 归纳问题线索
  │    4. supplementSources   — 补充联网来源（仅已授权）
  │    5. synthesizeFindings  — 整理发现 / 机会 / 待验证
  │    6. prepareProposal     — 草案准备
  ├─ 联网状态 → operation metadata: { online: boolean, supplementedSources: SourceCitation[] }
  ├─ 取消 → operation.cancel()，保留已完成步骤的中间结果
  ├─ 失败 → operation.retry()，使用当前选中资料
  └─ 完成 → 产出 ArtifactProposal，不自动保存
```

**关键边界**：
- 进度嵌在聊天中，不做独立任务中心。
- 不展示模型思维链。
- 草案出现 ≠ 写入画布。
- 来源变化时需提示用户重新检查。

### 10.4 Operation status

```
UI 概念：Operation 进度卡
         ├─ 状态标签：running / done / failed / cancelled
         ├─ 步骤列表：done / running / pending / failed
         ├─ 联网状态
         └─ 操作按钮：取消 / 重试

技术映射：
  ├─ Operation 是有生命周期的受控任务
  ├─ status: 'running' | 'succeeded' | 'failed' | 'cancelled'
  ├─ steps: Array<{ id, label, status: 'pending'|'running'|'done'|'failed' }>
  ├─ 每个步骤状态变化时更新 UI（不轮询模型内部状态）
  ├─ 取消 → 立即停止后续步骤，保留已完成步骤结果
  ├─ 失败 → 记录失败步骤，允许从失败点重试或从头重试
  └─ 来源变化 → 标记 operation 为 stale，提示用户重新检查
```

**视觉映射**：

| Operation status | UI 状态标签 | 步骤图标 |
|---|---|---|
| running | `running`（蓝灰） | 当前步骤脉冲 |
| succeeded | `done`（绿） | 全部对勾 |
| failed | `failed`（红） | 失败步骤红叉 |
| cancelled | `cancelled`（灰） | 已完成步骤保留对勾，当前步骤灰 |

### 10.5 ArtifactProposal

```
UI 概念：草案卡（draft-card）
         ├─ 头部：标签「研究分析草案 · 未保存」+ 标题 + 摘要
         ├─ 正文：主要发现 / 机会点 / 限制约束 / 待验证问题
         ├─ 来源区：SourceCitation 列表
         ├─ 操作：保存 / 继续追问 / 修改范围 / 放弃
         └─ 保存后 → 创建正式 research 对象

技术映射：
  ├─ ArtifactProposal 是 Operation 的输出，不是持久化对象
  ├─ proposal: {
  │    title, summary,
  │    findings: string[],
  │    opportunities: string[],
  │    constraints: string[],
  │    openQuestions: string[],
  │    sources: SourceCitation[]
  │  }
  ├─ proposal 生命周期：created → confirmed | discarded
  ├─ confirmed → 创建 ResearchAnalysis 对象（stable identity），写入画布
  ├─ discarded → 不创建任何对象，保留选中资料和输入
  └─ AI 不能自动 confirm
```

**视觉区别**：

| 状态 | 视觉 | 位置 |
|---|---|---|
| proposal（草案） | 品牌色浅底头部 + 「未保存」标签 | 聊天区 |
| confirmed（已确认） | 草案卡底部变绿色「已保存」提示 | 聊天区 |
| formal object（正式对象） | `research-obj` 编辑文档卡 | 画布 |

### 10.6 SourceCitation

```
UI 概念：来源条目
         ├─ 类型图标（图 / 文 / 链）
         ├─ 标题
         ├─ 域名 或 本地资料标识
         └─ 引用片段

技术映射：
  ├─ SourceCitation: {
  │    type: 'image' | 'text' | 'link',
  │    title: string,
  │    origin: string,        // 域名 或 '本地资料 · 类型'
  │    snippet: string,       // 引用片段
  │    refObjectId?: string   // 指向画布对象的 stable identity（本地资料）
  │  }
  ├─ 联网来源 → origin 为域名
  ├─ 本地资料 → origin 为 '本地资料 · 图片/文字'
  ├─ 点击来源 → 定位到画布中的原始资料（refObjectId）
  └─ 来源必须可回看，不可丢失
```

**展示规则**：

| 位置 | 展示内容 |
|---|---|
| 聊天消息 | 简短文字引用 |
| 草案卡来源区 | 完整 SourceCitation 列表 |
| 底部详情栏「来源」tab | 直接来源（一层） |
