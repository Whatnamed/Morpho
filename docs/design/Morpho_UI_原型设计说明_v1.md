# Morpho UI 原型设计说明 v1

> **用途**：本文件只用于生成 Morpho 的桌面端前端视觉 / 交互原型。它不是产品定义、技术方案、数据库设计或 AI 系统提示词。  
> **使用对象**：Open Design / agy CLI 或其他能够生成高保真前端原型的设计 Agent。  
> **优先级**：本文件是本轮原型的唯一界面依据。不要读取或推断完整 v3.1 产品文档中的后台机制、存储模型、项目记忆文件、Context / Thread、模型路由、归档格式等内容。  
> **原型目标**：快速做出一套“已经可以被使用”的 Morpho 体验样机，重点检验视觉气质、信息层级、画布工作方式与关键交互；所有数据和 AI 结果均为前端模拟。

---

## 0. 先理解：这次要做什么，不要做什么

### 要做

Morpho 是一个面向产品设计 / 工业设计概念阶段的 AI 辅助设计工作台。用户在一个连续项目空间里放入资料、形成设计定义、发展概念图、继续修改图像，并准备展板 / PPT 等交付内容。

本次原型要让人一眼看懂三件事：

1. **它不是普通生图工具**：用户在画布上同时看见资料、判断、方向、图像和交付内容；图像不是聊天记录里的附件。
2. **它不是普通白板**：右侧 AI 能理解用户当前选中的对象，并把分析、生成和修改结果自然放回画布。
3. **它不是 Figma / PPT 编辑器**：交付区域只做内容准备、素材引用、图注和缺口检查，不承担最终精细排版。

### 不做

以下内容不属于本轮原型，不要为了“功能完整”而自行添加界面：

- 真实 AI、模型选择、模型参数、Prompt 工程、调用日志、Token、任务队列；
- 数据库、云同步、账户体系、多人协作、权限、评论流；
- 项目记忆 / 阶段记录 / Context / Thread 的管理页或文件浏览器；
- 六阶段完成度、进度条、任务看板、KPI、日历、团队动态；
- CAD、3D 建模、工程结构、尺寸标注、BOM、供应链、制造验证；
- Office 文档编辑器、最终级展板排版、可编辑 PPTX、Figma 级图层系统；
- 默认展开的复杂版本网络、关系蜘蛛网、元数据表格；
- 大量通用圆角卡片组成的 SaaS 仪表盘。

**复杂逻辑应通过体验被感知，而不应被画成后台控制台。**

## 1. 原型交付范围

### 1.1 形式

制作一套可点击的高保真桌面端 Web 原型，默认画布尺寸按 **1440 × 1024** 设计。允许适度自适应，但不需要制作移动端。

- 所有内容使用固定的前端模拟数据；
- 不需要真实上传、真实解析、真实生成或真实导出；
- 关键交互需要能呈现状态变化，而不是只有静态页面；
- 默认进入“正在进行中的项目工作台”，让首次预览直接看到 Morpho 最有代表性的状态；
- 首页、空白项目、资产 / 搜索、交付准备等作为可访问状态或页面存在。

### 1.2 必须出现的 8 个体验状态

1. 项目首页；
2. 空白新项目；
3. 进行中的项目工作台：调研与设计定义视图；
4. 进行中的项目工作台：方向与视觉发展视图（默认打开）；
5. 选中对象后的聊天建议与底部详情状态；
6. 图像局部修改标注状态；
7. 资产 / 搜索 / 隐藏恢复抽屉状态；
8. 交付准备与“替换后续默认参考”的确认状态。

它们可以是路由、画布视图切换、抽屉、覆盖层或可点击状态，不要求每个状态都单独做成传统页面。

## 2. 视觉方向：安静、有物感的设计工作台

### 2.1 总体气质

做成一个**安静、成熟、带编辑感的创意工作台**，像设计师的桌面与项目墙，而不是黑色 AI 控制台、营销落地页或模板化企业后台。

关键词：

```text
quiet studio / editorial workspace / material board / precise but warm / image-led / calm confidence
```

### 2.2 颜色与材质

使用明亮、偏暖的中性底色，使产品图和参考图成为画面的视觉重点。

建议色彩关系：

- 主背景：温和的暖灰 / 浅纸色，例如 `#F4F3EF`；
- 画布：比面板略深或略暖的浅灰纸面，例如 `#EFEEE9`；
- 面板与浮层：接近白色但不纯白，例如 `#FBFAF7`；
- 主要文字：深炭灰 / 墨黑绿，例如 `#1E2521`；
- 次级文字与分割线：低对比灰褐；
- 唯一主强调色：克制的深鼠尾草绿或冷灰绿，用于主要动作、当前选择、默认参考；
- 状态颜色只作细小提示，不用整片高饱和填充。

避免：纯黑大面积背景、紫蓝霓虹渐变、玻璃拟态、过度毛玻璃、彩虹标签、科技 HUD。

### 2.3 排版与密度

- 使用现代无衬线字体；中文以系统 UI 字体为主，英文可用干净的现代字体；
- 标题简洁，不做巨大 Hero 文案；
- 画布对象有不同大小与节奏，避免整齐卡片网格；
- 常规圆角约 8–12px，图片可略大；
- 分区、面板和对象主要靠留白、轻边线、非常浅的色差区分；
- 按钮应清楚但不抢眼，少用胶囊形大按钮；
- 动效应短、克制，主要用于抽屉、选择态、详情展开和画布焦点。

### 2.4 图片与视觉素材

画布中的产品图应呈现为高质量概念设计视觉：克制、统一、偏真实产品渲染，不要赛博科幻，不要杂乱拼贴。若没有图像生成能力，可用风格统一的抽象产品渲染占位图、渐变材质构图或内嵌 SVG 近似表现；不要放随机 Unsplash 人像或与项目无关的图库照片。

## 3. 全局信息结构

Morpho 的工作台永远由五部分构成：

```text
顶部轻工具栏
+ 左侧轻量项目导航
+ 中央连续画布
+ 右侧连续 AI 聊天
+ 底部按需详情栏
```

### 3.1 顶部栏

高度克制，不做仪表盘。

左侧：

```text
Morpho 标志 / 返回项目首页
项目名称：夜航 — 夜间卫浴辅助系统
```

右侧：

```text
导入
搜索（⌘K）
输出与归档
轻量账户头像
```

可保留一个很轻的“已保存”文字或云点，但不要显示任务数、阶段完成度、模型名称、团队在线状态或操作流水。

### 3.2 左侧导航

默认窄栏，可展开。它的作用是**定位画布区域**，不是切换不同页面或不同 AI 聊天。

当前示例项目显示：

```text
项目概览 / 画布地图
输入与调研
设计定义
方向与视觉发展
交付准备
——
资产
已隐藏内容
```

规则：

- 导航只移动画布到对应位置；
- 不显示“第 3 步 / 共 6 步”或完成百分比；
- 不要把“探索”做成强制存在的单独任务页；
- 当前区域可有细小强调，不造成流程闯关感。

### 3.3 中央画布

画布是整个产品的主角：它比左右栏更开阔，支持自由摆放、缩放和横向阅读。

画布按从左到右的阅读线索弱组织：

```text
输入与调研 → 设计定义 → 方向与视觉发展 → 交付准备
```

但它不是节点图、泳道图或看板。对象的位置只帮助阅读，不改变对象的身份。

分区做成极浅的背景场或细小标题，不使用大边框容器。不同方向可在上下轻微分叉，主方向向右继续，交付区位于更右侧。

### 3.4 右侧 AI 聊天

右侧永远是连续聊天，不变成属性面板。

结构：

```text
小标题：对话
当前对象 Context 标签（可移除）
简短连续对话
必要时嵌入确认卡
输入框
自动执行 / 先确认切换
```

选中对象后，标签可呈现为：

```text
正在讨论  [柔光轨道 v2 ×] [方向 A ×]
```

输入框附近可以出现 2–4 个轻建议 chip，例如：

```text
继续发展  局部修改  生成使用场景  设为后续默认参考
```

**点击建议的规则**：只将自然语言填入输入框，例如“基于这张图继续发展，保留低位导向与暖光氛围”，不自动发送、不自动生成、不切换项目区域。

### 3.5 底部详情栏

未选中对象时隐藏或只留一条很薄的收起把手。

选中对象后出现紧凑标题栏；展开时可显示：

```text
[信息] [来源] [版本] [关联] [决策]
```

只展示与当前对象直接有关的一层内容：一张来源图、直接父 / 子版本、一个设计定义或交付模块引用。不要显示整张项目关系网。

## 4. 原型固定示例项目：夜航 / Nightrail

所有工作台内容必须围绕同一个连贯项目，避免 Agent 自己临时拼出不同题材的图片和文案。

### 4.1 项目一句话

```text
夜航 / Nightrail
为独居老人的夜间起身与卫浴路径设计一套低施工、非医疗化的连续辅助系统。
```

它不是医疗设备，也不是工程化无障碍改造。核心是把低位柔光、可触摸导向与隐蔽支撑融入普通居家空间。

### 4.2 视觉语言

产品应呈现为：

```text
温和暖白墙面 + 低饱和橄榄灰 / 深砂岩色轨道 + 柔暖导光
圆角但不玩具化
家具感、家居感、低施工感
不做医院蓝、不做厚重金属扶手、不做复杂智能屏
```

主要视觉内容：

- 普通卧室通向卫浴的夜间过道；
- 墙面低位柔光轨道 / 扶持结构；
- 一张产品主视觉：轨道、转角连接、隐藏灯带与触觉导向一体；
- 一组细节图：触感截面、转角、磁吸夜灯、安装方式；
- 一张使用场景；
- 一张 CMF 小板：暖灰、砂岩、深橄榄、柔光白。

### 4.3 项目内容与用词

请使用自然、简洁的中文 UI 文案。推荐对象标题：

**输入与调研**

- 课程要求.pdf
- 夜间起身路径参考 · 6 张
- 现有扶手产品参考 · 8 张
- 研究与分析

**关键结论**

- 连续支持比单点扶手更符合真实动作路径
- 安全产品需要降低“医疗器械感”
- 租住 / 老房场景不适合大施工

**设计定义**

- 核心问题：让独居老人从床边到卫浴的最后几米更容易辨认、扶持与转身
- 原则：低施工、连续支撑、低干扰照明、居家语气
- 避免项：医院感、复杂电子交互、厚重外露五金

**概念方向**

- 方向 A：柔光轨道（主方向）
- 方向 B：家具化支撑岛（备选）
- 方向 C：软性引导带（已淘汰）

**交付准备**

- A1 展板 · 问题与机会
- A2 展板 · 核心方案
- 6 页汇报 PPT
- 待补：安装逻辑示意
- 待补：夜间使用场景

## 5. 关键界面与状态说明

### 5.1 项目首页

目标：表达“继续真实项目”而非管理项目。

布局建议：

- 顶部左侧 Morpho 标志；右侧搜索、恢复项目备份、头像；
- 主标题保持克制，例如“继续设计”；
- 一个较大的最近项目卡：`夜航 / Nightrail`，封面是柔光轨道产品主视觉，附一句项目说明、最近工作重点“方向与视觉发展”、上次打开时间；
- 旁边或下方放 2 个较小项目：例如“折叠露营灯”“桌面收纳模块”；
- 明确的新建项目按钮；
- 不要项目进度、任务量、团队动态、日历、数据图表。

点击“夜航”进入默认的主工作台；点击“新建项目”进入空白项目状态。

### 5.2 空白新项目

目标：体现“不用先填 Brief，也可以从任何东西开始”。

画布应为空、安静，中央仅有低压力的开始提示：

```text
从一句想法、一张图、一个文件开始
在这里输入、粘贴或拖入资料
```

提供三个清楚入口：

```text
开始聊天 / 导入资料 / 粘贴图片
```

不要表单、项目分类、领域选择、标签或复杂创建向导。

### 5.3 调研与设计定义视图

这是同一张连续画布的左中段视图。

画布中应包括：

- 左侧：一个课程 PDF 文件对象；一组参考图片以“合集”形式松散排布；
- 中部：一张 `研究与分析` 对象，内部有“发现 / 设计机会 / 现实约束 / 待验证”四段简短内容；
- 研究对象附近：3 张独立的 `关键结论` 小对象；
- 右侧：一张更大、文档式的 `设计定义` 对象，不要做成营销卡片；
- 右侧聊天中显示 AI 对资料的简短分析与下一步提示，例如“可以保留这三条结论，或继续补充居家场景资料。”

研究与分析是候选理解，不要在卡面上显示“已确认”。关键结论本身就是用户保留后的内容。

### 5.4 默认主画面：方向与视觉发展

这是原型首次打开时必须呈现的状态。

画布视野应停在项目中段 / 右中段，让用户同时看见：

- 左边缘还能看到设计定义的一小部分；
- 中部有方向 A、B、C 的轻量方向对象和各自预览图；
- A 作为主方向，向右连接一张大幅产品图 `柔光轨道 v2`；
- 该图旁有 2–3 张相邻变体 / 细节 / 场景图，保持视觉发展关系但不画满箭头；
- 一张图有轻量标签 `后续默认参考`；
- B 显示小标签 `备选`；C 显示低调 `已淘汰`，仍留在画布而非消失；
- 右侧聊天正在围绕选中主图讨论；
- 底部详情栏展开 `版本`：显示直接父版本 → 当前图 → 两个直接子结果，关系清晰但非常轻。

主画面不应像“瀑布流图库”。画布里应有图、方向文字、局部标注和留白，像真实项目工作区。

### 5.5 选中对象后的建议状态

用户框选 3 张方向预览图后：

- 画布显示清晰但克制的选择边框；
- 底部详情栏切换为多选摘要；
- 聊天输入框上方出现建议：

```text
比较这些方案
找共同线索
分析差异与风险
作为多参考生成
```

点击“比较这些方案”后，输入框内出现一段可编辑文本：

```text
比较这三张预览在连续支撑、居家感和安装复杂度上的差异，并说明各自适合继续发展的部分。
```

不要自动发送。

### 5.6 图像局部修改状态

选中 `柔光轨道 v2` 后，用户点“局部修改”。

画面应表现：

- 图片上出现一个手绘感但精确的圈选区域或箭头，标向转角连接件；
- 右侧输入框已有文本：

```text
保留整体比例与柔光轨道语言，把转角连接件做得更一体化、少一些外露五金感。
```

- 输入框旁明确显示 `自动执行` 或 `先确认`；
- 点击执行后可模拟在原图右侧出现两张新变体，作为新对象而非覆盖原图。

圈选只表达“优先改这里”，不要把界面画成 Photoshop 专业像素编辑器。

### 5.7 后续默认参考替换确认

选择另一张更成熟的主图，点击“设为后续默认参考”时，右侧聊天内嵌一张确认卡，而不是居中弹窗。

确认卡需要用自然语言说明：

```text
用“柔光轨道 v3”替换当前后续默认参考。
之后相关生成会默认延续它的比例、轨道结构、材质和柔光基线；已有图和交付内容不会被替换。
```

卡片底部提供：

```text
只替换默认参考
替换并标记直接延展素材待复核
```

不要显示技术参数、Prompt、模型名字或长篇影响列表。

### 5.8 资产、搜索与隐藏恢复

资产打开后从左侧出现可收起的面板，不离开画布。

资产过滤器只需：

```text
全部 / 原始资料 / 生成结果 / 文档 / 已用于交付
```

每个条目提供最小动作：定位、拖到画布、查看用于哪里。

项目内搜索可做成轻量命令面板或覆盖层。示例搜索词为 `暖光`，结果分成：

```text
画布内容
素材与文件
交付引用
```

隐藏内容应显示 `已隐藏` 标记，动作是 `恢复并定位`。不要把隐藏、删除和已淘汰混为同一种“归档”。

### 5.9 交付准备

画布移动到最右侧的 `交付准备` 区域。

这里呈现的是内容结构，不是最终展板编辑器：

- 有一个 `A1 展板 · 核心方案` 交付模块，内部以粗略、清晰的内容块组织：标题、主图引用、两个细节引用、说明文字、图注；
- 有一个 `6 页汇报 PPT` 模块，显示页面主题而非完整 PPT；
- 有 `待补：安装逻辑示意`、`待补：夜间使用场景` 两个轻量缺口提示；
- 显示一张产品图被稳定引用进展板模块：源图仍在上游画布中，交付区只是一个可裁切 / 可替换的引用实例；
- 右侧聊天可以建议“先复用已有主图和细节，再补安装逻辑示意”。

不要出现专业排版标尺、图层、复杂网格、PPT 母版、导出格式参数。

### 5.10 局部失败与恢复状态

任选一次模拟“局部修改”失败，提示应只出现在任务附近或聊天中：

```text
这次修改没有完成。原图与修改要求已保留。
[重试] [修改后重试] [取消并保留原图]
```

不要全屏错误页、全局错误中心或常驻任务中心。

## 6. 对象的界面表现规则

| 对象 | 视觉表现 | 不要做成 |
|---|---|---|
| 图片 | 完整、可缩放的图像对象；角落只留轻角色标签 | 小缩略图信息卡、瀑布流商品卡 |
| 文件 | 文件名、类型、简短预览、可阅读入口 | 多列表格文件管理器 |
| 图片合集 | 可展开的一组图片，初次打开可呈现为轻量堆叠 / 网格 | 永久文件夹或语义分类 |
| 研究与分析 | 可阅读的结构化内容对象，段落短、层级清楚 | 冗长调研报告、密集表格 |
| 关键结论 | 一张只表达一个意思的小文字对象 | 多标签任务卡 |
| 设计定义 | 更大、更像工作文件的核心对象 | 大色块营销卡 |
| 概念方向 | 名称、一句话策略、少量关键词、轻状态 | 阶段任务 / 看板列 |
| 说明标注 | 箭头、圈选、短文字、编号，可随图移动 | 永久覆盖在所有图片上的杂乱批注 |
| 交付模块 | 内容结构、稳定引用、文字、缺口提示 | 完整 Figma / Keynote 画板 |

状态规则：

- 方向只使用：`待预览`、`主方向`、`备选`、`已淘汰`、必要时 `待复核`；
- 图像使用角色标签：`预览`、`主图`、`场景`、`CMF`、`细节`、`设计示意`；
- `后续默认参考` 是很轻的特殊标签，不是锁定一切的状态；
- 交付模块只提示真实缺口，例如 `待补：安装逻辑示意`，不显示进度百分比或“已完成”。

## 7. 原型中的关键可点击行为

至少实现下列行为的可见状态切换：

1. 首页 → 打开夜航项目；
2. 新建项目 → 空白画布；
3. 左侧导航 → 画布平移 / 聚焦到不同区域，不切换成另一个聊天；
4. 点击或框选对象 → 选择态、Context 标签、底部详情栏变化；
5. 点击聊天建议 → 只填充输入框；
6. 点击“局部修改” → 进入圈选与文字要求状态；
7. 点击执行 → 新图作为相邻新对象出现；
8. 点击“设为后续默认参考” → 右侧确认卡；
9. 打开资产 / 搜索 → 抽屉或命令面板，不离开工作台；
10. 将图拖向交付模块或点击“用于交付” → 出现稳定引用实例；
11. 点击失败提示的“重试”或“修改后重试” → 只更新局部状态。

## 8. 严格的反例清单

以下设计方向视为不符合本项目：

- 把每个工作重点做成独立全屏页面或六步流程向导；
- 在左侧显示“1/6、2/6”或阶段完成百分比；
- 右栏被对象属性、模型参数、历史任务、Prompt 详情占满；
- 使用通用三栏 AI 聊天网页布局，中央没有真实画布空间；
- 让所有对象都变成统一尺寸、统一圆角、统一阴影的卡片；
- 生成结果只进入聊天记录、不回到画布；
- 用大量彩色标签解释状态；
- 让“设为后续默认参考”看起来像永久锁定、必须先完成的关卡；
- 交付区变成具有标尺、图层、复杂拖拽工具的 Figma 克隆；
- 把项目记忆、阶段记录、Context、归档 JSON 等后台概念直接展示给用户；
- 设计成赛博紫、黑色 HUD、霓虹未来感，或把“老年辅助”项目做成医院系统。

---

## 9. 完成标准

完成后，用户应能在 20 秒内通过视觉感知到：

- 这是一个围绕“项目持续推进”的设计工作台；
- 画布里既有资料、判断、图像，也有正在形成的交付内容；
- AI 对当前选择的对象有反应，但不会抢走用户控制权；
- 图片可以继续发展、局部改、生成场景和细节，不必等待某个强制阶段；
- 这个工具帮用户组织设计过程，但不会把过程变成一套沉重的管理系统。

优先保证视觉完成度、核心状态完整性和整套项目内容的一致性。功能数量少于预期时，宁可删掉低价值功能，也不要牺牲主工作台、对象选择、连续视觉发展和交付准备的表达质量。
